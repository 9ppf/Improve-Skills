# 冒泡排序（起泡排序）—— 例题、算法与抢分技巧

## 一、题目

有关键字序列：`38, 19, 65, 13, 97, 49, 41, 95, 1, 73`，采用冒泡排序方法进行升序排序，请写出每趟排序的结果。

---

## 二、推演过程

*(冒泡排序的规则：从左往右，相邻两个数比较，大的往后挪。每一趟都会把当前未排序部分里最大的那个数"冒"到最后面)*

**初始状态**：`38, 19, 65, 13, 97, 49, 41, 95, 1, 73`

| 趟数 | 冒泡元素 | 结果序列 | 已排好部分 |
| :--- | :--- | :--- | :--- |
| 第 1 趟 | 97 冒泡到最后 | `19, 38, 13, 65, 49, 41, 95, 1, 73, 97` | 97 |
| 第 2 趟 | 95 冒泡到倒数第二 | `19, 13, 38, 49, 41, 65, 1, 73, 95, 97` | 95, 97 |
| 第 3 趟 | 73 冒泡到倒数第三 | `13, 19, 38, 41, 49, 1, 65, 73, 95, 97` | 73, 95, 97 |
| 第 4 趟 | 65 冒泡到位 | `13, 19, 38, 41, 1, 49, 65, 73, 95, 97` | 65, 73, 95, 97 |
| 第 5 趟 | 49 冒泡到位 | `13, 19, 38, 1, 41, 49, 65, 73, 95, 97` | 49, ... |
| 第 6 趟 | 41 冒泡到位 | `13, 19, 1, 38, 41, 49, 65, 73, 95, 97` | 41, ... |
| 第 7 趟 | 38 冒泡到位 | `13, 1, 19, 38, 41, 49, 65, 73, 95, 97` | 38, ... |

## 三、核心思想（大白话）

就像水里吐泡泡，**越大的泡泡浮力越大，跑得越快**。

算法从左到右扫一遍，两两比较。如果左边的比右边的大，就交换它们。

扫完一趟，最大的数就一定跑到了最右边。下一趟就不管最右边那个排好的数了，继续在剩下的里面找最大的。重复这个过程直到全部排好。

## 四、完整代码 + 下标级注释

*(考试中通常写带 flag 优化的版本，这样当数组已经有序时可以直接跳出)*

```c
void BubbleSort(SeqList R[], int n)
{
    int i, j;
    SeqList temp;
    int flag; // 优化标志位：标记本趟是否发生了交换

    // i 控制趟数，n 个元素最多需要 n-1 趟
    for (i = 1; i < n; i++)
    {
        flag = 0; // 每趟开始前，标志位清零

        // j 控制每趟比较的次数。每趟过后，最后 i 个元素已经排好，不用再比了
        for (j = 1; j <= n - i; j++)
        {
            // 相邻元素比较：如果前面的比后面的大（升序规则）
            if (R[j].key > R[j+1].key)
            {
                // 交换相邻的两个元素
                temp = R[j];
                R[j] = R[j+1];
                R[j+1] = temp;

                flag = 1; // 发生了交换，标志位置 1
            }
        }

        // 优化点：如果这一趟扫下来，一次交换都没发生，说明已经完全有序了
        if (flag == 0)
            return; // 直接结束算法
    }
}
```

## 五、考场极速抢分技巧（必看！）

### 🃏 1. 手算推演技巧（大题）

- **横线法**：在纸上推演时，每排好一趟，就在数组末尾画一条横线。比如第一趟结束：`19, 38, 13, 65, 49, 41, 95, 1, 73, | 97`。横线左边的参与下一趟，右边的不看。
- **盯紧末尾**：如果题目问"第 k 趟排序的结果"，你其实只需要保证当前最大的 k 个数已经按从小到大的顺序排在最后面了。
- **全对检查**：最后一定要看有没有完全排好，以及如果某一趟没有发生任何交换，直接写最终结果。

### 💻 2. 代码填空/改错技巧

- **内层循环边界**：`j < n - i` 或者 `j <= n - i - 1`（如果下标从 0 开始的话）。因为每次外层循环 i 增加，后面的 i 个数已经排好了，不需要再比较。
- **交换条件**：`R[j].key > R[j+1].key`。如果是降序排序，改成 `<`。
- **优化标志 flag**：考代码题必考。`flag` 初始为 0，一旦发生交换设为 1。最后判断如果 `flag == 0` 就可以 `return`。

### 🎯 3. 选择题秒杀结论（直接背）

| 维度 | 结论 |
| :--- | :--- |
| **稳定性** | **稳定**。如果两个相等的元素相邻比较，不会发生交换，所以相对顺序不变 |
| **最好情况** | 原数组已经升序。比较 **n−1** 次，移动 **0** 次。总时间 **O(n)** |
| **最坏情况** | 原数组是逆序。需要比较和移动 **O(n²)** 次。总时间 **O(n²)** |
| **平均情况** | **O(n²)** |
| **空间复杂度** | **O(1)**。只需要一个临时变量 `temp` 用于交换 |
| **特点** | 每一趟排序后，都会有一个元素（当前最大值）被放置在最终位置上 |

## 六、核心规律与避坑指南（重点）

### 🎯 1. 考试做题的"秒杀"应用（如何快速检查对错）

只要题目要求的是**升序排序**（从小到大），那么规律永远是：**每一趟都把当前未排序部分最大的数放在后面**。

- 写完第 1 趟：看一眼最后一个数，必须是整个数组里的最大值（比如本题的 97）。
- 写完第 2 趟：看一眼最后两个数，它们必须是按照从小到大排好的（如 `..., 95, 97`）。
- 写完第 3 趟：最后三个数必须是整个数组里最大的三个数且排好序（如 `..., 73, 95, 97`）。

👉 **检查秘籍**：如果你发现某趟写完后，最大的数没在最后面，绝对是你中间交换写错了，立刻重头推演。

### ⚠️ 2. 唯一需要注意的"陷阱"（降序排序）

如果题目要求的是**降序排序**（从大到小），那么规律就完全反过来了：

- 每比较一次，**小的数**就会像泡泡一样往后挪。
- 每一趟会把**最小的数**放在最后面。

（因为比较条件变成了 `if (R[j].key < R[j+1].key)`，谁小谁往后换，最后面的自然就是最小的）。
