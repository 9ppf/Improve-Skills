# 第八章 查找 综合笔记（模块一至模块四）

## 模块一：查找的基本概念与线性表的查找（顺序、折半、分块）

### 第八章 查找 - 基础概念与线性查找

#### 1. 查找的基本概念

- **查找表**：用于查找的数据集合（由同一类型的数据元素构成）。
- **静态查找表**：只进行查找操作，不改变表结构（如：顺序查找、折半查找、分块查找）。
- **动态查找表**：查找过程中可能插入或删除元素（如：二叉排序树、哈希表）。
- **关键字**：唯一标识一个数据元素的数据项。
- **平均查找长度（ASL - Average Search Length）**：查找算法性能的核心指标。
- 公式：$ASL = \sum_{i=1}^{n} P_i C_i$（$P_i$ 为查找第 $i$ 个元素的概率，$C_i$ 为找到该元素需要比较的次数）。

#### 2. 顺序查找（线性查找）

- **适用条件**：顺序存储或链式存储，**表内元素有序或无序皆可**。
- **过程**：从表的一端开始，逐个比较。
- **ASL（等概率情况）**：
  - 查找成功：$ASL_{成功} = (n+1)/2$
  - 查找失败：$ASL_{失败} = n+1$（需比较 $n$ 个元素和 1 个越界判断/哨兵）
- **优化**：若表内元素**有序**，查找失败时不需要比到最后一个，可提前结束。$ASL_{失败} = n/2 + n/(n+1)$。
- **时间复杂度**：$O(n)$

#### 3. 折半查找（二分查找）

- **适用条件（必须同时满足）**：
  1. **顺序存储**（必须能随机访问，链表不行）。
  2. **元素有序**（递增或递减）。
- **过程**：设置 `low`、`high`、`mid` 指针，每次比较后缩小一半范围。
- **判定树（重点）**：
  - 折半查找的过程可用二叉树表示（判定树），是一棵**平衡二叉树**。
  - 树高 $h = \lfloor \log_2 n \rfloor + 1$。
  - **ASL**：$ASL_{成功} \approx \log_2(n+1) - 1$。
- **时间复杂度**：$O(\log_2 n)$

#### 4. 分块查找（索引顺序查找） ⭐（你的易错点）

- **结构**：将表分成若干块，建立**索引表**（存储每块的最大关键字和起始地址）。
- **核心要求（必考）**：
  - **块间有序**：第 $i$ 块的最大关键字 < 第 $i+1$ 块的最小关键字。
  - **块内无序**：块内部元素可以无序（若块内也有序，则退化为折半查找）。
  - **块长可不等**：通常为提升效率，规定等长或最优块长。
- **存储方式**：通常为顺序存储。
- **查找过程**：
  1. 在索引表中确定待查记录所在的块（可用顺序查找或折半查找）。
  2. 在块内进行顺序查找。
- **平均查找长度**：$ASL = ASL_{索引} + ASL_{块内}$。
  - 若均为顺序查找，且等分成 $b$ 块，每块 $s$ 个元素（$n=bs$），则 $ASL = (b+1)/2 + (s+1)/2$。
- **最优块长**：当 $s = \sqrt{n}$ 时，ASL 最小，为 $\sqrt{n} + 1$。
- **时间复杂度**：$O(\sqrt{n})$

## 模块二：树表查找（树形结构的动态查找）

### 第八章 查找 - 树表查找

#### 1. 二叉排序树（BST / 二叉查找树）

- **定义**：
  - 若左子树非空，则左子树上所有节点的值均**小于**根节点的值。
  - 若右子树非空，则右子树上所有节点的值均**大于**根节点的值。
  - 左右子树也分别是一棵二叉排序树。
- **重要性质**：对 BST 进行**中序遍历**，可以得到一个递增的有序序列。
- **查找效率**：
  - 最好情况（平衡状态）：$O(\log_2 n)$。
  - 最坏情况（退化为单链表）：$O(n)$。
- **删除操作**：
  - 叶子节点：直接删除。
  - 只有一个子节点：子节点直接顶替。
  - 有两个子节点：用其**直接前驱**或**直接后继**替换，然后删除前驱/后继节点。

#### 2. 平衡二叉树（AVL树）

- **定义**：任意节点的左、右子树高度之差的绝对值不超过 1。
- **平衡因子（BF）**：节点左子树高度减去右子树高度（$BF \in \{-1, 0, 1\}$）。
- **性质**：高度为 $h$ 的 AVL 树包含的最少节点数 $N_h = N_{h-1} + N_{h-2} + 1$。
- **失衡调整（四种旋转）**：
  - **LL型**（在左孩子的左子树插入）：**右旋**。
  - **RR型**（在右孩子的右子树插入）：**左旋**。
  - **LR型**（在左孩子的右子树插入）：先左旋（变成LL），再右旋。
  - **RL型**（在右孩子的左子树插入）：先右旋（变成RR），再左旋。

#### 3. B 树（多路平衡查找树）

- **应用场景**：用于磁盘等外存储器（降低树高，减少 I/O 次数）。
- **m 阶 B 树的特性**：
  1. 每个节点最多有 $m$ 棵子树（$m-1$ 个关键字）。
  2. 若根节点不是叶子，至少有 2 棵子树。
  3. 除根节点外，所有非叶节点至少有 $\lceil m/2 \rceil$ 棵子树。
  4. 所有叶子节点都在同一层，且不带信息（可视为查找失败的节点）。

#### 4. B+ 树（数据库的最爱）

- **与 B 树的核心区别**：
  1. 有 $n$ 个关键字的节点只包含 $n$ 棵子树（B 树是 $n+1$ 棵）。
  2. **所有关键字及数据都存在叶子节点中**（非叶节点仅作索引，不含数据）。
  3. 叶子节点之间用指针连成一个有序链表，支持**范围查询**。

## 模块三：散列（哈希）查找

### 第八章 查找 - 散列（Hash）查找

#### 1. 基本概念

- **散列函数**：$H(key)$，根据关键字直接计算存储地址。
- **冲突（碰撞）**：不同关键字计算出相同的散列地址（$H(key_1) = H(key_2)$）。
- **同义词**：发生冲突的两个关键字互称同义词。
- **装填因子（$\alpha$）**：$\alpha = \frac{表中记录数 n}{散列表长度 m}$。$\alpha$ 越大，冲突概率越高。

#### 2. 常见散列函数构造方法

- **除留余数法（最常用）**：$H(key) = key \bmod p$，其中 $p$ 通常取**小于或等于表长 $m$ 的最大质数**。
- 直接定址法：$H(key) = a \cdot key + b$（不会产生冲突）。
- 数字分析法。
- 平方取中法。

#### 3. 处理冲突的方法（重点）

##### （1）开放定址法（闭散列）

- **线性探测法**：冲突时，往后找下一个空位 $H_i = (H(key) + i) \bmod m$。
  - *缺点*：容易产生"堆积（聚集）"现象，降低查找效率。
- **平方探测法（二次探测法）**：$H_i = (H(key) \pm i^2) \bmod m$。可以避免堆积，但可能无法探测到所有空位。
- **双散列法**：$H_i = (H(key) + i \cdot H_2(key)) \bmod m$。
- **伪随机序列法**。
- **注意**：开放定址法删除元素时，不能直接删除，只能做**逻辑删除标记（墓碑标记）**，否则会截断后续冲突元素的查找路径。

##### （2）拉链法（链地址法 / 开散列）

- **原理**：将所有同义词存储在一个线性链表中。
- **优点**：不产生堆积，删除方便，适合表长不确定的情况。

#### 4. 查找性能

- 哈希查找的效率取决于：散列函数、处理冲突的方法、装填因子 $\alpha$。
- **时间复杂度**：理想情况下为 $O(1)$。与表中元素个数 $n$ 无关，只与 $\alpha$ 有关。

## 模块四：各查找算法性能对比总结（冲刺背诵版）

### 第八章 查找 - 算法性能大对比

| 查找算法 | 存储结构要求 | 元素要求 | 平均时间复杂度 | 特点 / 备注 |
| :--- | :--- | :--- | :--- | :--- |
| **顺序查找** | 顺序或链式 | 无要求 | $O(n)$ | 简单，效率低。有序表可优化失败情况。 |
| **折半查找** | **仅限顺序** | **必须有序** | $O(\log_2 n)$ | 效率高，但插入删除困难（需移动元素）。 |
| **分块查找** | 通常顺序 | **块间有序** | $O(\sqrt{n})$ | 综合了顺序和折半的优点，适合动态变化。 |
| **二叉排序树** | 链式 | 无（构造时满足BST） | 最好 $O(\log n)$ <br> 最坏 $O(n)$ | 动态查找，插入删除方便。 |
| **平衡二叉树(AVL)** | 链式 | AVL特性 | $O(\log_2 n)$ | 严格平衡，查找效率高，但插入/删除常需旋转。 |
| **B / B+树** | 多叉树 | 满足多路平衡 | $O(\log_m n)$ | 适合外存（磁盘）查找，B+树适合数据库索引。 |
| **哈希查找** | 散列表 | 无 | 理想 $O(1)$ | 基于计算，查找速度极快，不适合范围查询。 |
