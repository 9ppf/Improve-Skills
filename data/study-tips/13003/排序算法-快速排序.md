# 快速排序（分治法）—— 例题、算法与抢分技巧

## 一、题目

对于数据序列：`31, 5, 44, 55, 61, 200, 30, 60, 20, 1, 80, 150, 4, 29`，写出采用**快速排序**算法排序的过程。

---

## 二、推演过程（挖坑填数法）

*(假设默认取当前序列的第一个元素为基准数)*

**初始状态**：`31, 5, 44, 55, 61, 200, 30, 60, 20, 1, 80, 150, 4, 29`

### 🎯 第一趟：以 31 为基准（31 归位）

- **过程**：取 31 为基准（挖坑）。右指针找小于 31 的数（29）填左坑，左指针找大于 31 的数（44）填右坑。交替进行，直到两指针相遇，将 31 填入最终坑位。
- **第一趟结果**：`29, 5, 4, 1, 20, 30, 31, 60, 200, 61, 80, 150, 55, 44`
  *(注：此时 31 已归位，左边全小于 31，右边全大于 31)*

### 🎯 第二趟：分别对左右子序列划分

- **左子区** `[29, 5, 4, 1, 20, 30]`（以 29 为基准）：变为 `[20, 5, 4, 1, 29, 30]`
- **右子区** `[60, 200, 61, 80, 150, 55, 44]`（以 60 为基准）：变为 `[44, 55, 60, 80, 150, 61, 200]`
- **第二趟结果**：`20, 5, 4, 1, 29, 30, 31, 44, 55, 60, 80, 150, 61, 200`

### 🎯 第三趟：继续拆分子序列

- **左侧** `[20, 5, 4, 1]`（以 20 为基准）：变为 `[1, 5, 4, 20]`
- **右侧** `[80, 150, 61, 200]`（以 80 为基准）：变为 `[61, 80, 150, 200]`
- **第三趟结果**：`1, 5, 4, 20, 29, 30, 31, 44, 55, 60, 61, 80, 150, 200`

### 🎯 第四趟：收尾

- 对 `[5, 4]` 划分（以 5 为基准）：变为 `[4, 5]`
- **最终结果**：`1, 4, 5, 20, 29, 30, 31, 44, 55, 60, 61, 80, 150, 200`

## 三、核心思想与"中间"概念辨析

- **大白话思想**：随便抓一个数当"基准"。比基准小的全扔左边，比基准大的全扔右边。然后对左右两边重复此操作。
- **理解"基准数跑到中间"**：这里的"中间"不是指物理位置的正中央，而是**数值大小的分界线**。一趟划分结束后，基准数的左边全部 ≤ 它，右边全部 ≥ 它。**这意味着该基准数已经被放到了它在完全排序后最终应在的位置上（即"归位"），后续的排序不需要再动它。**

## 四、完整代码 + 下标级注释

```c
// 核心划分函数
int Partition(SeqList R[], int low, int high)
{
    SeqList pivot = R[low]; // 【挖坑】暂存基准数，留出坑位

    while (low < high) // 左右指针未相遇
    {
        // 1. 右侧找小于基准的数，填左坑
        while (low < high && R[high].key >= pivot.key) high--;
        R[low] = R[high];

        // 2. 左侧找大于基准的数，填右坑
        while (low < high && R[low].key <= pivot.key) low++;
        R[high] = R[low];
    }
    R[low] = pivot; // 相遇，基准数填入最终位置
    return low;     // 返回基准数位置
}

// 递归主函数
void QuickSort(SeqList R[], int low, int high)
{
    if (low < high)
    {
        int pivotPos = Partition(R, low, high); // 划分
        QuickSort(R, low, pivotPos - 1);        // 递归左半区
        QuickSort(R, pivotPos + 1, high);       // 递归右半区
    }
}
```

## 五、考场极速抢分技巧与答题规范（必看）

### ✍️ 1. 卷面答题规范与草稿技巧

- **卷面格式（大忌）**：答题卡上**必须写成一整行完整的序列**（用逗号隔开），绝对不能写成分组带括号的形式（如 `[左子区] 基准 [右子区]`），否则可能被判定为格式错误而扣分。
- **高分细节**：在每一趟的结果中，可以把刚刚**归位的基准数画个下划线**，或者旁边用文字简注（如：`此时31已归位`），这能向阅卷老师清晰展示你完全懂算法的逻辑。
- **草稿推演（神技）**：在草稿纸上，强烈建议用 `[左子区] 基准 [右子区]` 的分组写法。这样能清晰看出下一次递归该处理哪一部分，避免在一长串数字里看错行。

### 🃏 2. 检查对错的秒杀技巧

- **立刻找基准**：写完任意一趟结果，立刻找到这一趟选出的基准数。检查：**它左边的数是否全部 ≤ 它？右边的数是否全部 ≥ 它？** 如果有违背，说明你"挖坑填数"时写反了，立刻重推。
- **位置锁定规律**：每一趟划分完，至少有一个数字（基准数）被放到了最终完全排好序后应该呆的位置上。越往后排，归位的数字越多。

### 🎯 3. 选择题秒杀结论（直接背）

| 维度 | 结论 |
| :--- | :--- |
| **稳定性** | **不稳定**（相同大小的数在跨区间长途搬运时，相对顺序会发生改变） |
| **时间复杂度** | 平均情况 **O(n log n)**；最坏情况（原数组基本有序，每次划分只能分出一个空子区）退化为 **O(n²)** |
| **空间复杂度** | **O(log n)**（因为递归调用需要占用栈空间，这是它区别于直接插入、冒泡等简单排序最大的不同点） |
| **适用场景** | 数据量大、分布随机、对运行速度要求高的场景 |
| **最坏情况陷阱** | 如果选择题说"快速排序在任何情况下都是最快的"，这绝对是**错误**的。面对基本有序的数据，它反而最慢 |
