# 希尔排序（增量插入排序）—— 例题、算法与抢分技巧

## 一、题目

对于数据序列：`66, 61, 200, 30, 80, 150, 4, 8, 100, 12, 20, 31, 1, 5, 44`，写出采用希尔排序算法排序的每一趟结果。设增量序列 **d = {5, 3, 1}**。

---

## 二、推演过程

*(希尔排序的核心就是：按照给定的间隔 d，把数组分成几组，每组内部独立进行"直接插入排序"，然后再换下一个 d)*

### 🎯 第一趟：d = 5（分成 5 组）

**分组规则**：把每隔 5 个位置的数字挑出来组成一组。

| 组号 | 原序列 | 排序后 |
| :--- | :--- | :--- |
| 第 1 组 | 66, 150, 20 | 20, 66, 150 |
| 第 2 组 | 61, 4, 31 | 4, 31, 61 |
| 第 3 组 | 200, 8, 1 | 1, 8, 200 |
| 第 4 组 | 30, 100, 5 | 5, 30, 100 |
| 第 5 组 | 80, 12, 44 | 12, 44, 80 |

**将排好序的组按原位置放回**：

> 结果：`20, 4, 1, 5, 12, 66, 31, 8, 30, 44, 150, 61, 200, 100, 80`

### 🎯 第二趟：d = 3（分成 3 组）

**分组规则**：在上一趟的结果上，每隔 3 个位置的数字挑出来。

| 组号 | 原序列 | 排序后 |
| :--- | :--- | :--- |
| 第 1 组 | 20, 5, 31, 44, 200 | 5, 20, 31, 44, 200 |
| 第 2 组 | 4, 12, 8, 150, 100 | 4, 8, 12, 100, 150 |
| 第 3 组 | 1, 66, 30, 61, 80 | 1, 30, 61, 66, 80 |

**将排好序的组按原位置放回**：

> 结果：`5, 4, 1, 20, 8, 30, 31, 12, 61, 44, 100, 66, 200, 150, 80`

### 🎯 第三趟：d = 1（分成 1 组，即全体）

**分组规则**：间隔为 1，就是对整个数组进行最后一次直接插入排序。

因为前面的 d=5 和 d=3 已经让数组变得"基本有序"了，所以这次直接插入排序会非常快，移动次数极少。

> **最终结果**：`1, 4, 5, 8, 12, 20, 30, 31, 44, 61, 66, 80, 100, 150, 200`

---

## 三、核心思想（大白话）

希尔排序就是"**分组做直接插入排序**"。

比如有 15 个人排队，一开始大家乱站（d=5）。长官把队伍按 1,6,11 号、2,7,12 号这样分成 5 个小组，各自小组内部先排好。虽然整体看去还有点乱，但大数字已经基本跑到后面了，小数字跑到前面了。

然后缩小间隔（d=3），再分组排一次。

最后间隔变成 1（d=1），大家整体排一次。因为队伍已经"基本有序"了，最后一次排序几乎不用怎么挪动位置，效率极高。

## 四、完整代码 + 下标级注释

*(注意：代码中的 d 通常是从 n/2 开始折半，但题目中给定了特定的增量序列 5, 3, 1。实际考试中如果是写代码，通常写成增量折半的形式)*

```c
void ShellSort(SeqList R[], int n)
{
    int i, j, d;
    SeqList x;

    // 外层循环：控制增量 d 的变化（d 逐渐缩小，直到等于 1）
    for (d = n / 2; d >= 1; d = d / 2)
    {
        // 内部逻辑与直接插入排序几乎一样，只是把"步长 1"变成了"步长 d"
        for (i = d + 1; i <= n; i++) // 从第 d+1 个元素开始，往后遍历
        {
            x = R[i];                // 暂存当前要插入的元素
            j = i - d;               // 比较的起点是与它相隔 d 个位置的元素

            // 只要没越界，且前面的元素比新元素大
            while (j > 0 && R[j].key > x.key)
            {
                R[j + d] = R[j];     // 把前面的元素往后挪 d 个位置（而不是 1 个位置）
                j = j - d;           // 继续往前跳 d 个位置去比较
            }

            R[j + d] = x;            // 找到位置，放入坑中
        }
    }
}
```

## 五、考场极速抢分技巧（必看！）

### 🃏 1. 手算推演技巧（大题）

- **画竖线分组法**：在纸上写数字时，第一个 d=5，你就在第 5 个数字后面画条竖线，把数字分组写。比如第一组 `66, 150, 20` 单独抽出来写一行，排好序再填回去，这样绝对不会错。
- **别弄丢顺序**：把每一组排好序后，一定要原封不动地填回原来的空位，不能连着写，否则后面就全乱了。
- **最后一趟必是完整的有序序列**：只要 d=1 那一趟写完，最终结果绝对是从小到大完全排好的，可以用这个来检查自己有没有算错。

### 💻 2. 代码填空/改错技巧（只考过一两次，但需防备）

- **注意看循环条件**：`while (j > 0 && R[j].key > x.key)` 没变。
- **核心变动**：挪动元素时是 `R[j+d] = R[j]`，往前跳的时候是 `j = j - d`。**所有的 1 都变成了 d**。

### 🎯 3. 选择题秒杀结论（直接背）

| 维度 | 结论 |
| :--- | :--- |
| **稳定性** | **不稳定**（因为相同大小的数字可能会在不同的分组里被跨过去）。这是它和直接插入排序最大的区别 |
| **时间复杂度** | 取决于增量序列。平均大约是 **O(n^1.3)** 到 **O(n^1.5)**，远好于直接插入的 O(n²) |
| **空间复杂度** | **O(1)** |
| **适用场景** | 适用于数据量较大且不要求稳定性的场景。它是第一个打破 O(n²) 瓶颈的排序算法 |
