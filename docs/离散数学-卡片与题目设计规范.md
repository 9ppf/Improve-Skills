# 离散数学 — 卡片与题目设计规范

> 本文档是离散数学（02324）知识框架和题库的设计标准，后续章节补充照此执行。
> 对标《离散数学学习闭环标准模板.md》，补充卡片设计、题目设计、考核对照的量化标准。

---

## 一、核心原则

1. **考核要求驱动**：每张概念卡的知识点必须能追溯到考核要求的某个条目
2. **覆盖率优先**：每个知识点至少被1道题目覆盖，不允许"有知识点无题目"
3. **题型匹配层级**：识记/领会偏选择填空，简单应用偏计算，综合应用偏证明/简答
4. **一章一章推进**：先把一章的闭环跑通做样板，确认没问题再扩展
5. **只改两个JSON**：补充知识点时只改知识框架JSON和题库JSON，页面代码不动

## 二、卡片设计规范

### 2.1 卡片类型

| 卡片类型 | cardType值 | 适用考核层级 | 内容特点 | 正面 | 背面 |
|---|---|---|---|---|---|
| 记忆卡 | `memory` | 识记 + 领会 | 定义、术语、概念、关系、性质 | 概念名+一句话总结 | 知识点列表 + 举例 + 考点 |
| 计算卡 | `calculation` | 简单应用 | 公式、等值式、演算步骤、求范式 | 概念名+一句话总结 | 公式/步骤 + 例题 + 考点 |

**综合应用不单独建卡**：离散数学的综合应用是"证明题"和"推理题"，属于能力而非固定知识点，放题库出 proof 类型题目。

### 2.2 拆卡原则

| 规则 | 说明 |
|---|---|
| 每卡知识点数 | 3-7个，超过7个必须拆卡 |
| 拆卡依据 | 按考核层级拆（识记/领会→记忆卡，简单应用→计算卡），或按主题拆（概念→定律→应用） |
| 定律类拆卡 | 当一组定律超过7条时，按"基本定律→运算定律→高级定律"分层拆卡 |
| 推理规则类拆卡 | 当推理规则超过7条时，按"基本推理→高级推理"分层拆卡 |
| 同一考核主题 | 可拆成1张记忆卡+1张计算卡，分别覆盖领会层和应用层 |
| 不同考核主题 | 各自独立建卡，不合并 |
| 去重 | 拆卡时检查是否与其他卡有知识点重复，重复的只保留在一张卡中 |

### 2.3 卡片字段规范

```json
{
  "term": "命题基本定律",
  "priority": "重点",
  "level": "理解",
  "summary": "命题逻辑的6条基本等值律",
  "cardType": "memory",
  "points": [
    "双重否定律：¬¬A ⇔ A",
    "幂等律：A ⇔ A∨A, A ⇔ A∧A",
    "同一律：A∨F ⇔ A, A∧T ⇔ A",
    "零律：A∨T ⇔ T, A∧F ⇔ F",
    "排中律：A∨¬A ⇔ T",
    "否定律：A∧¬A ⇔ F"
  ],
  "ex": "¬¬(p∨q) ⇔ p∨q（双重否定律）",
  "exam": "常考选择题和等值演算题，需熟记每条定律的公式",
  "hint": "6条基本定律口诀：双重否定回到原，幂等自己并自己，同一与F/T不变，零律与T/F变T/F，排中必有一真，否定必有一假"
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| term | ✅ | 概念名，与题库cardId完全一致（含空格） |
| priority | ✅ | 重点(🔴)/一般(🟡)/了解(⚪) |
| level | ✅ | 计算/理解/背诵/应用 |
| summary | ✅ | 一句话，不超过30字 |
| cardType | ✅ | memory 或 calculation |
| points | ✅ | 3-7个知识点，每个一句话 |
| ex | ✅ | 具体举例，帮助理解 |
| exam | 推荐 | 考点提示 |
| hint | 推荐 | 记忆提示/口诀 |

### 2.4 知识点编写规范

- **一句话一个知识点**：不要把多个概念塞进一个点
- **按考核层级排列**：识记在前，领会在中，简单应用在后
- **可追溯**：每个知识点应对应考核要求中的某个条目
- **具体不抽象**：写"双重否定律：¬¬A ⇔ A"而不是"双重否定律"
- **公式要完整**：计算卡的知识点必须包含完整公式，不能只写名称

## 三、题目设计规范

### 3.1 题目数量标准

| 规则 | 公式 | 说明 |
|---|---|---|
| 每卡最少题数 | `max(4, ⌈知识点数 × 0.7⌉)` | 知识点越多题越多 |
| 每知识点覆盖 | 至少1题 | 不允许有知识点0题覆盖 |
| 重点知识点 | 2题 | priority为重点(🔴)的知识点 |
| 综合应用题 | 每个考核主题1-2题 | 放题库，用proof类型 |

**计算示例**：
- 记忆卡6个知识点 → max(4, ⌈6×0.7⌉) = max(4, 5) = 5题
- 计算卡5个知识点 → max(4, ⌈5×0.7⌉) = max(4, 4) = 4题
- 考核主题3个 → 综合应用3×1-2 = 3-6题

### 3.2 题型分配规范

#### 记忆卡（识记+领会层）

| 题型 | 占比 | 示例 |
|---|---|---|
| 选择题(choice) | 40% | "下列等值式中，属于排中律的是（ ）" |
| 填空题(fill) | 40% | "双重否定律的公式是___" |
| 简答题(shortAnswer) | 20% | "简述真值表法判断公式类型的步骤" |

#### 计算卡（简单应用层）

| 题型 | 占比 | 示例 |
|---|---|---|
| 计算题(calculate) | 40% | "利用分配律将 A∨(B∧C) 展开" |
| 填空题(fill) | 30% | "德摩根律将否定号向内分配时，___与___互换" |
| 简答题(shortAnswer) | 30% | "简述等值演算的替换策略" |

#### 综合应用题（放题库，不绑卡）

| 题型 | 占比 | 示例 |
|---|---|---|
| 证明题(proof) | 60% | "证明：(A→B)∧(A→¬B) ⇔ ¬A（归谬律）" |
| 简答题(shortAnswer) | 40% | "用真值表法证明两个公式等值，并说明步骤" |

**离散数学特色**：综合应用以**证明题(proof)**为主，这是与数据结构（以算法设计题为主）的核心区别。证明题考察逻辑推理能力，是离散数学的考核重点。

### 3.3 题目字段规范

```json
{
  "id": "q-02324-001",
  "type": "choice|fill|calculate|shortAnswer|proof",
  "question": "题干",
  "options": ["A. ...", "B. ..."],
  "answer": "B",
  "blanks": [{"answer": "答案", "synonyms": ["别名1", "别名2"]}],
  "chapter": "第1章 命题与命题公式",
  "cardId": "命题基本定律",
  "src": "ai|textbook",
  "explanation": "解析：为什么选B"
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| id | ✅ | 格式 `q-02324-XXX`，递增 |
| type | ✅ | choice/fill/calculate/shortAnswer/proof |
| question | ✅ | 题干 |
| answer | ✅ | 选择题填选项字母，证明题填完整证明过程 |
| options | choice必填 | 4个选项，带A./B./C./D.前缀 |
| blanks | fill必填 | 数组，每个blank含answer和synonyms |
| chapter | ✅ | 格式 `第N章 章名`，与知识框架一致 |
| cardId | ✅ | 与概念卡term完全一致（含空格） |
| src | ✅ | ai(AI生成) 或 textbook(教材原题) |
| explanation | 推荐 | 答案解析 |

### 3.4 证明题(proof)特殊规范

```json
{
  "id": "q-02324-150",
  "type": "proof",
  "question": "证明：(A→B)∧(A→¬B) ⇔ ¬A（归谬律）",
  "answer": "证明：\n(A→B)∧(A→¬B)\n⇔ (¬A∨B)∧(¬A∨¬B) （蕴涵等值式）\n⇔ ¬A∨(B∧¬B) （分配律）\n⇔ ¬A∨F （否定律）\n⇔ ¬A （同一律）\n证毕。",
  "chapter": "第1章 命题与命题公式",
  "cardId": "蕴涵与等价等值式",
  "src": "ai",
  "explanation": "归谬律证明：蕴涵等值式+分配律+否定律+同一律"
}
```

| 规范 | 说明 |
|---|---|
| answer格式 | 分步骤写，每步标注所用定律/规则 |
| 步骤分隔 | 用换行符 `\n` 分隔步骤 |
| 最后一步 | 必须有"证毕"或"Q.E.D."标记 |
| keywords | 可选，用于自动评分时的关键词匹配 |

### 3.5 题目质量要求

- **不重复**：同一知识点不要出两道几乎一样的题
- **题型多样**：每张卡至少覆盖2种题型
- **选项规范**：选择题4个选项，干扰项要有合理性
- **填空规范**：一个空一个答案，synonyms覆盖常见等价表述（如 `¬` 和 `!` 和 `非`）
- **简答规范**：参考答案分点列出，不超过5个要点
- **证明规范**：每步必须标注依据定律，步骤完整可追溯
- **符号一致**：使用标准逻辑符号（¬ ∧ ∨ → ↔ ⇔ ∀ ∃），不用编程符号

## 五、离散数学 vs 数据结构 差异对照

| 维度 | 离散数学(02324) | 数据结构(13003) |
|---|---|---|
| 综合应用题型 | **证明题(proof)** | 简答/算法设计(shortAnswer/essay) |
| 计算卡内容 | 等值演算、求范式、推理 | 地址计算、算法分析、复杂度 |
| 记忆卡内容 | 定义、定律、性质、规则 | 定义、术语、特点、ADT |
| 题型种类 | choice + fill + calculate + shortAnswer + **proof** | choice + fill + calculate + shortAnswer + essay |
| 定律/规则类 | 需要拆卡（定律多、规则多） | 不涉及 |
| 符号系统 | ¬ ∧ ∨ → ↔ ⇔ ∀ ∃ | 代码/伪代码 |
| 知识点特点 | 偏理论，定义+定理+证明 | 偏实践，概念+操作+实现 |

## 七、执行流程（每章补充照此执行）

### Step 1：整理考核要求
- 从PDF提取该章考核要求，写入知识框架JSON的考核要求section
- 确保每个考核主题的每个层级都有具体条目

### Step 2：对比现有概念卡
- 逐条对照考核要求，标记"已覆盖/部分覆盖/完全缺失"
- 输出缺失清单

### Step 3：拆卡与建卡
- 按拆卡原则（每卡3-7点）拆分或新建概念卡
- 记忆卡（识记+领会）和计算卡（简单应用）分开
- 定律/规则类按层次拆分（基本→运算→高级）
- 综合应用不建卡
- 检查去重：拆卡后检查知识点是否与其他卡重复

### Step 4：出题
- 按题目数量标准计算每卡题数
- 按题型分配规范确定题型比例
- 确保每个知识点至少1题覆盖
- 综合应用按每主题1-2题放题库，以proof为主
- 证明题answer必须分步骤、标注定律依据

### Step 5：验证闭环
- 运行覆盖率检查脚本
- 填写考核要求→卡片→题目映射表
- 浏览器验证页面显示正常

### Step 6：版本更新
- 更新self-study.json中02324科目的v参数
- 运行build.py构建

## 八、常见错误与防范

| 错误 | 后果 | 防范 |
|---|---|---|
| 定律超过7条不拆卡 | 卡片臃肿，题目无法覆盖 | 定律类拆卡：基本→运算→高级 |
| 推理规则超过7条不拆卡 | 覆盖率低，题数不足 | 推理类拆卡：基本推理→高级推理 |
| cardId与term不一致（含空格） | 题目无法匹配到卡片 | 复制粘贴term，不手动输入 |
| 综合应用建成卡片 | 正反面不好设计，无法自测 | 综合应用只放题库proof题 |
| 全出选择题 | 无法覆盖简单应用和综合应用 | 题型分配规范：计算卡40%计算题 |
| 知识点无题目覆盖 | 学习闭环断裂 | 覆盖率检查：每点至少1题 |
| 填空题缺blanks字段 | 页面渲染崩溃 | fill题必须有blanks数组 |
| 题型名用calc/short | 题型无法识别 | 用标准名：calculate/shortAnswer |
| 证明题无步骤标注 | 无法评分，学习效果差 | 每步标注定律依据，最后写证毕 |
| 拆卡后知识点重复 | 背诵卡重复显示 | 拆卡时去重，只保留在一张卡中 |
| 同一定律出现在多张卡 | 维护困难，改一处忘另一处 | 每个知识点只归属一张卡 |
