## 一、前期准备

### 1.1 购买服务器

1. 打开 [腾讯云轻量应用服务器](https://cloud.tencent.com/product/lighthouse)
2. 点击 **立即选购**
3. 配置选择：

| 配置项 | 推荐值 | 说明 |
|--------|--------|------|
| 地域 | 上海 / 广州 / 北京 | 选离你近的，国内访问速度差不多 |
| 镜像 | 系统镜像 → **Ubuntu 22.04 LTS** | 不要选 Windows，Linux 跑服务器更稳 |
| 套餐 | 2核2G（最便宜的） | 完全够用，内存占用 < 500MB |
| 购买时长 | 1个月 | 先试试，好用再续 |
| 带宽 | 3Mbps 或 4Mbps | 默认就行，刷题够用 |

4. 支付：微信 / 支付宝 / 储蓄卡都支持

### 1.2 获取登录信息

购买完成后，在 [腾讯云控制台](https://console.cloud.tencent.com/lighthouse) 找到你的服务器：

1. 记下 **公网 IP**（例如 `115.159.77.65`）
2. 点击服务器 → 右上角 **重置密码** → 设置一个 root 密码（复杂一点，包含大小写+数字）
3. 左侧菜单 **防火墙** → 确认有"放通全部端口"规则，或者手动添加你要用的端口

> 💡 **踩坑记录**：腾讯云轻量服务器默认有"放通全部端口"的规则（1-65535），如果有这条规则，就不用额外加端口了。如果没有，需要手动添加。

## 二、连接服务器

### 方式一：用腾讯云网页终端（最简单，推荐新手）

1. 在服务器详情页，点击右上角 **登录**
2. 选择 **标准登录方式** → 输入用户名和密码
3. 成功进入命令行界面

> 💡 **注意**：腾讯云轻量服务器的默认用户名是 `ubuntu`（不是 root），这是 Ubuntu 系统的惯例。root 用户也存在，但默认禁用密码登录，用 ubuntu 用户登录后可以用 `sudo` 执行管理员命令。

### 方式二：用本地 SSH 工具（Windows PowerShell）

打开 PowerShell，输入：

```bash
ssh ubuntu@你的公网IP
# 例如：ssh ubuntu@115.159.77.65
```

输入密码即可登录。

## 三、部署步骤详解

登录服务器后，依次执行以下命令。每一条都有详细解释。

### 3.1 更新系统 + 安装基础工具

```bash
sudo apt update && sudo apt upgrade -y
```

**命令解释**：
- `sudo` = Super User Do，以管理员权限执行（因为修改系统软件需要管理员权限）
- `apt update` = 更新软件源列表，让系统知道有哪些最新版本的软件可以安装
- `apt upgrade -y` = 升级所有已安装的软件到最新版本，`-y` 表示自动确认所有提示
- `&&` = 前面的命令成功了才执行后面的

```bash
sudo apt install -y python3 python3-pip python3-venv git git-lfs
```

**命令解释**：
- `apt install` = 安装软件
- `python3` = Python 3 解释器，项目是用 Python 写的后端
- `python3-pip` = Python 的包管理工具，用来安装 Python 依赖库
- `python3-venv` = Python 虚拟环境工具（本次部署没用到，但建议装上备用）
- `git` = 代码版本管理工具，用来从 GitHub 拉取代码
- `git-lfs` = Git Large File Storage，用来管理大文件（比如图片、音频）
- `-y` = 自动确认安装

### 3.2 创建项目目录

```bash
sudo mkdir -p /opt/improve-skills
```

**命令解释**：
- `mkdir` = Make Directory，创建文件夹
- `-p` = Parents，如果父目录不存在也一起创建（比如 /opt 不存在的话会自动创建）
- `/opt/improve-skills` = 项目存放路径，`/opt` 是 Linux 里存放第三方软件的标准目录

```bash
cd /opt/improve-skills
```

**命令解释**：
- `cd` = Change Directory，切换当前工作目录
- 执行后，你当前所在的位置就变成了 `/opt/improve-skills`，后续操作都在这个目录下进行

### 3.3 从 GitHub 拉取代码

```bash
sudo git clone https://github.com/你的用户名/Improve-Skills.git .
```

**命令解释**：
- `git clone` = 克隆（下载）一个 Git 仓库到本地
- 后面的 URL 是你的 GitHub 仓库地址
- 最后的 `.` = 当前目录，意思是把代码下载到当前目录，而不是新建一个子文件夹

> ⚠️ **注意**：最后的点号 `.` 很重要！如果不加，会在当前目录下新建一个 `Improve-Skills` 子文件夹，路径就变成 `/opt/improve-skills/Improve-Skills/` 了，后续命令会找不到文件。

```bash
sudo git lfs pull
```

**命令解释**：
- `git lfs pull` = 拉取 Git LFS 管理的大文件（图片、音频等）
- 如果项目里有大文件，必须执行这一步，否则图片会显示不出来

### 3.4 安装 Python 依赖

```bash
sudo pip3 install -r requirements.txt
```

**命令解释**：
- `pip3 install` = 用 pip 安装 Python 包
- `-r requirements.txt` = 从 requirements.txt 文件中读取要安装的包列表，批量安装
- `requirements.txt` 是项目根目录下的一个文件，列出了所有依赖库

### 3.5 构建项目

```bash
sudo python3 build.py
```

**命令解释**：
- 执行项目根目录下的 `build.py` 脚本
- 这个脚本会把 `Workbench/` 目录下的页面和资源处理一遍，生成最终的可部署版本
- 看到 `Writing workbench` 字样就说明构建成功

### 3.6 配置 DeepSeek API Key

```bash
sudo nano /etc/improve-skills.env
```

**命令解释**：
- `nano` = 一个简单的文本编辑器（比 vim 好上手）
- `/etc/improve-skills.env` = 环境变量文件的存放路径
- `/etc/` 是 Linux 里存放配置文件的标准目录

在打开的编辑器里写入：

```
DEEPSEEK_API_KEY=你的DeepSeek密钥
```

**保存退出方法**：
1. 按 `Ctrl + O`（字母O，不是零）→ 保存
2. 按 **回车** → 确认文件名
3. 按 `Ctrl + X` → 退出编辑器

> 💡 **为什么用环境变量文件？**
> API Key 是敏感信息，不能硬编码在代码里（不安全，而且换环境不方便）。
> 放在环境变量文件里，代码启动时自动读取，既安全又灵活。

### 3.7 配置 systemd 服务（开机自启 + 崩溃自动重启）

创建服务文件：

```bash
sudo nano /etc/systemd/system/improve-skills.service
```

**命令解释**：
- 在 `/etc/systemd/system/` 目录下创建服务配置文件
- `.service` 后缀表示这是一个 systemd 服务
- systemd 是 Linux 的服务管理器，负责管理开机自启、进程守护等

写入以下内容：

```ini
[Unit]
Description=Improve Skills Workbench
After=network.target

[Service]
Type=simple
User=ubuntu
WorkingDirectory=/opt/improve-skills
EnvironmentFile=/etc/improve-skills.env
ExecStart=/usr/bin/python3 dev_server.py --port 8081 --prod
Restart=always
RestartSec=5
StandardOutput=journal
StandardError=journal

[Install]
WantedBy=multi-user.target
```

**逐行解释**：

**[Unit] 段 — 服务的基本描述**
- `Description` = 服务的描述文字，查看状态时会显示
- `After=network.target` = 在网络就绪后再启动这个服务（因为网站需要网络）

**[Service] 段 — 服务的运行配置**
- `Type=simple` = 服务类型是普通的前台进程
- `User=ubuntu` = 用 ubuntu 用户运行服务（不要用 root，更安全）
- `WorkingDirectory=/opt/improve-skills` = 工作目录，代码在哪个目录下
- `EnvironmentFile=/etc/improve-skills.env` = 从这个文件读取环境变量（API Key 就在这里）
- `ExecStart` = 启动服务时执行的命令
  - `/usr/bin/python3` = Python 解释器的完整路径
  - `dev_server.py` = 后端服务的入口文件
  - `--port 8081` = 指定监听端口为 8081
  - `--prod` = **生产模式**，启用 gzip 压缩和 HTTP 缓存，大幅提升加载速度（自动包含 --no-build 和 --no-watch）
- `Restart=always` = 进程挂了就自动重启（永远重启）
- `RestartSec=5` = 重启前等待 5 秒（避免死循环重启）
- `StandardOutput=journal` = 标准输出写到系统日志里
- `StandardError=journal` = 错误输出也写到系统日志里

**[Install] 段 — 安装配置**
- `WantedBy=multi-user.target` = 在多用户模式下启用（也就是正常开机时自动启动）

> 💡 **生产模式 --prod 的优化效果**
> - **gzip 压缩**：JSON/HTML/JS/CSS 等文本资源自动压缩传输，体积减少 70%-90%，加载速度大幅提升
> - **HTTP 缓存**：
>   - JS/CSS/图片等静态资源：缓存 7 天（第二次访问直接从浏览器缓存读取，零延迟）
>   - HTML 入口页面：缓存 5 分钟（保证更新不会太晚）
>   - API 接口：不缓存（保证数据实时性）
> - 同时自动禁用文件监听（省内存）和初始构建（启动更快）

> 💡 **踩坑记录 1 — 端口占用**
> 8000 和 8080 端口可能被服务器上的其他服务占用。
> 启动失败时看日志，如果报 `Address already in use` 就是端口被占了，换一个端口就行（比如 8081、9000 等）。
>
> 💡 **踩坑记录 2 — User 不要写成 root**
> 用 root 运行服务不安全，而且如果你的代码是用 ubuntu 用户拉取的，权限可能不一致。
> 建议用 `User=ubuntu`。
>
> 💡 **踩坑记录 3 — 修改服务文件后要 daemon-reload**
> 修改了 .service 文件后，必须执行 `systemctl daemon-reload` 让 systemd 重新加载配置，否则不生效。
> 而且如果服务在运行中修改了配置，旧进程和新配置对不上会报 `Current command vanished from the unit file` 错误，需要 stop 再 start。

保存退出后，启动服务：

```bash
sudo systemctl daemon-reload
```

**命令解释**：
- 让 systemd 重新加载所有服务配置文件
- 每次修改了 .service 文件后都必须执行一次

```bash
sudo systemctl start improve-skills
```

**命令解释**：
- 启动 improve-skills 服务
- `start` 是启动，`stop` 是停止，`restart` 是重启

```bash
sudo systemctl enable improve-skills
```

**命令解释**：
- 设置服务开机自启
- `enable` 是启用自启，`disable` 是禁用自启

```bash
sudo systemctl status improve-skills
```

**命令解释**：
- 查看服务的运行状态
- 绿色的 `active (running)` 表示运行正常
- 红色的 `failed` 表示启动失败，需要看日志排查

## 四、验证部署

### 4.1 本地验证（在服务器上）

```bash
curl http://localhost:8081/api/health
```

**命令解释**：
- `curl` = 命令行的 HTTP 请求工具
- 向本地的 8081 端口发一个请求，测试服务是否正常
- 应返回 `{"status": "ok", ...}` 类似的 JSON

```bash
sudo ss -tlnp | grep 8081
```

**命令解释**：
- `ss` = 查看网络端口监听状态（比 netstat 更现代）
- `-t` = 只看 TCP 端口
- `-l` = 只看正在监听的端口
- `-n` = 用数字显示（不解析域名）
- `-p` = 显示哪个进程在监听
- `| grep 8081` = 只看包含 8081 的行
- 如果看到 `0.0.0.0:8081` 说明服务在正常监听，外部可以访问

### 4.2 浏览器访问

在电脑/手机浏览器打开：

```
http://你的公网IP:8081/Workbench/此刻便是春天.html
```

例如：
```
http://115.159.77.65:8081/Workbench/此刻便是春天.html
```

> 💡 **关于中文文件名**
> 首页文件名是「此刻便是春天.html」，浏览器地址栏里会自动把中文转成 URL 编码（类似 `%E6%AD%A4%E5%88%BB...`），不影响访问。
> 如果觉得不好看，可以改成英文的（比如 `index.html`）。

验证以下功能：

1. ✅ 页面正常加载，不报错
2. ✅ 练习测验能做题、提交、判分
3. ✅ 错题本能显示错题
4. ✅ AI 对话/AI 解答功能正常（需要 API key 配好）
5. ✅ 手机 4G 网络也能打开

## 六、常见问题 & 踩坑记录

### Q: 浏览器打不开页面，显示"响应时间过长"？

**排查步骤**：

1. **先 ping 一下 IP**（在本地电脑执行）
   ```
   ping 你的公网IP
   ```
   - ping 不通 → IP 地址错了，或者服务器关机了
   - ping 得通 → 网络没问题，继续往下查

2. **看服务有没有在跑**（在服务器执行）
   ```bash
   sudo systemctl status improve-skills
   ```
   - `active (running)` → 服务在跑，继续查
   - `failed` → 启动失败，看日志找原因

3. **看端口有没有在监听**（在服务器执行）
   ```bash
   sudo ss -tlnp | grep 8081
   ```
   - 有输出 → 端口监听正常
   - 没输出 → 服务没正常监听端口

4. **本地测试能不能访问**（在服务器执行）
   ```bash
   curl http://localhost:8081/api/health
   ```
   - 返回 JSON → 服务本身没问题，是外部网络/防火墙的问题
   - 连不上 → 服务真的没启动

5. **检查防火墙**
   - 腾讯云控制台 → 防火墙 → 确认端口开放
   - 或者服务器内部的 ufw 防火墙：`sudo ufw status`

> 💡 **本次部署踩坑**：ping 得通、服务也在跑、端口也在监听，但浏览器就是打不开。
> 后来发现是等待时间不够，刚启动服务需要等几秒钟。另外腾讯云防火墙规则生效也可能有延迟。
> 解决方法：多等一会儿，或者刷新页面试试。

### Q: 启动失败，报 `Address already in use`（端口被占用）？

**原因**：端口被别的进程占了。

**解决方法**：换一个端口。

1. 修改服务文件
   ```bash
   sudo nano /etc/systemd/system/improve-skills.service
   ```
   把 `--port 8081` 改成别的端口，比如 `--port 9000`

2. 重新加载配置并重启
   ```bash
   sudo systemctl daemon-reload
   sudo systemctl restart improve-skills
   ```

3. 确认防火墙开放了新端口

> 💡 **本次部署踩坑**：8000 和 8080 都被占用了，最后用了 8081。
> 腾讯云轻量服务器默认可能有一些服务占着常用端口，换个不常用的就行。

### Q: 修改服务文件后，报 `Current command vanished from the unit file`？

**原因**：服务正在运行时，你修改了 .service 文件，但没有先 stop 就 daemon-reload + restart，导致旧进程和新配置对不上。

**解决方法**：先 stop，再 reload，再 start

```bash
sudo systemctl stop improve-skills
sudo systemctl daemon-reload
sudo systemctl start improve-skills
```

### Q: AI 功能用不了？

**排查步骤**：
1. API key 是否正确配置：`cat /etc/improve-skills.env`
2. 重启服务：`sudo systemctl restart improve-skills`
3. 看日志有没有报错：`sudo journalctl -u improve-skills -n 20`
4. DeepSeek 账户余额是否充足

### Q: 数据会丢吗？

存在服务器硬盘上，只要服务器不删、硬盘不挂，就不会丢。建议每周备份一次 `data/` 目录。

### Q: 手机访问慢？

腾讯云国内节点访问速度应该很快。如果慢，检查：
1. 服务器地域是否选太远了
2. 图片/照片是否太大
3. 可以考虑加 CDN 加速（一般不需要）

## 七、域名配置（可选，以后想用域名时参考）

### 7.1 域名购买

- 国内推荐：腾讯云域名注册、阿里云域名注册
- 价格：`.top`/`.xyz` 第一年几块钱，`.com`/`.cn` 几十块一年
- 免费域名：基本没有靠谱的，不建议用

### 7.2 备案（必须，国内服务器）

- 服务器在国内的话，域名必须备案才能用
- 在腾讯云/阿里云控制台申请备案
- 一般需要 1-2 周时间
- 备案需要身份证、手机号、邮箱等信息

### 7.3 DNS 解析

备案通过后：
1. 进入域名控制台 → 解析设置
2. 添加一条 A 记录：
   - 主机记录：`@`（表示主域名）或 `www`
   - 记录类型：A
   - 记录值：你的服务器公网 IP

### 7.4 配置 Nginx 反向代理

装 Nginx：

```bash
sudo apt install -y nginx
```

创建站点配置：

```bash
sudo nano /etc/nginx/sites-available/improve-skills
```

写入：

```nginx
server {
    listen 80;
    server_name 你的域名.com;

    location / {
        proxy_pass http://127.0.0.1:8081;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

启用站点：

```bash
sudo ln -s /etc/nginx/sites-available/improve-skills /etc/nginx/sites-enabled/
sudo nginx -t  # 测试配置是否正确
sudo systemctl reload nginx
```

然后访问 `http://你的域名.com` 就能打开了，不需要加端口号。

### 7.5 配置 HTTPS（可选，更安全）

用 Let's Encrypt 免费证书：

```bash

sudo certbot --nginx -d 你的域名.com
```

按提示操作就行，certbot 会自动配置 Nginx 和证书续期。

## 九、实战踩坑记录（2026-09-28 部署经验）

> 本章记录第一次部署到腾讯云服务器时遇到的所有问题、排查思路和解决方案，供以后参考。

### 9.1 本次做了什么

1. 在腾讯云购买了轻量应用服务器（2核2G，Ubuntu 22.04）
2. 将项目部署到服务器，配置 systemd 开机自启
3. 给服务器添加了 **生产模式（--prod）**，包含两个核心优化：
   - **gzip 压缩**：JSON/HTML/JS/CSS 自动压缩，体积减少 70%-90%
   - **HTTP 缓存**：静态资源缓存 7 天，第二次访问秒开

---

### 9.2 遇到的问题 & 排查思路 & 解决方案

#### 问题 1：端口被占用（8000、8080 都不行）

**现象**：服务启动失败，日志报 `Address already in use`

**排查思路**：
- 看服务状态 → `failed`
- 看日志 → 明确报了端口被占用
- 结论：服务器上有其他服务占了常用端口

**解决方案**：
- 换端口，从 8000 → 8080 → 8081，直到找到空闲端口
- 命令：修改服务文件里的 `--port` 参数，然后 daemon-reload + restart

---

#### 问题 2：修改服务文件后报 `Current command vanished`

**现象**：修改 .service 文件后重启服务，报 `Current command vanished from the unit file`

**原因**：服务正在运行时修改了配置文件，直接 `daemon-reload + restart` 导致旧进程和新配置对不上了

**解决方案**：
- 正确的顺序是：**先 stop → 再 daemon-reload → 再 start**
- 命令：
  ```bash
  sudo systemctl stop improve-skills
  sudo systemctl daemon-reload
  sudo systemctl start improve-skills
  ```

---

#### 问题 3：浏览器打不开页面（响应超时）

**现象**：服务在跑、端口在监听、ping 也通，但浏览器就是打不开

**排查思路（从外到内，逐层排查）**：

1. **网络层**：`ping IP` → 通的，说明网络没问题
2. **服务层**：`systemctl status` → `active (running)`，服务在跑
3. **端口层**：`ss -tlnp | grep 8081` → 在监听，而且是 `0.0.0.0`
4. **应用层**：`curl http://localhost:8081/api/health` → 返回正常，服务本身没问题
5. **防火墙**：腾讯云控制台看了，有"放通全部端口"的规则

**结论**：都没问题，但就是打不开

**解决方案**：
- 等了一会儿自己好了
- 可能原因：腾讯云防火墙规则生效有延迟，或者服务刚启动需要预热
- 经验：遇到这种情况，先别慌，等 1-2 分钟再试试

---

#### 问题 4：git pull 后代码没更新（最坑的一个）

**现象**：`git log` 显示有最新提交，但 `--prod` 参数用不了

**排查过程（交叉验证，层层深入）**：

**第 1 层：看 git 提交记录**
```bash
git log --oneline -5
```
- 显示有 `feat: 添加生产模式` 那条提交
- 以为代码更新了，但这是**假象**

**第 2 层：直接搜文件内容**
```bash
grep -n "\-\-prod" /opt/improve-skills/dev_server.py
```
- 什么都没搜到
- 说明文件里根本没有新代码，git pull 没真正成功

**第 3 层：实际运行测试**
```bash
python3 dev_server.py --port 9999 --prod --no-build
```
- 报 `unrecognized arguments: --prod`
- 实锤了：代码确实没更新

**为什么 git pull 没成功？（一步步找原因）**：

1. **首先发现权限问题**
   ```
   fatal: detected dubious ownership in repository
   ```
   - 原因：git 认为 `/opt/improve-skills` 目录的所有者不安全
   - 解决：`git config --global --add safe.directory /opt/improve-skills`

2. **然后遇到 GitHub 网络不稳定**
   ```
   GnuTLS recv error (-110): The TLS connection was non-properly terminated.
   ```
   - 原因：国内服务器访问 GitHub 经常抽风，TLS 连接断开
   - 重试几次也不行

3. **又遇到 Git LFS 卡住**
   - `git pull` 时卡在下载 LFS 大文件（图片等），一直 0%
   - 加 `GIT_LFS_SKIP_SMUDGE=1` 跳过 LFS 也还是不行

4. **还出现了合并冲突**
   - 因为之前 pull 失败了一半，留下了烂摊子
   - 状态变成了 MERGING，各种命令都不好使

**最终解决方案：换思路，不用 git 了**

直接用 **jsDelivr CDN** 下载单个文件（国内有节点，速度快）：
```bash
cd /opt/improve-skills
sudo curl -O https://cdn.jsdelivr.net/gh/9ppf/Improve-Skills@master/dev_server.py
```

然后验证：
```bash
grep -n "\-\-prod" dev_server.py
```
- 搜到了 `--prod` 相关代码，成功了！

---

### 9.3 排查问题的方法论总结

#### 原则 1：从外到内，逐层排查

遇到问题不要瞎猜，按顺序来：

```
浏览器 → 网络 → 防火墙 → 端口 → 服务 → 应用 → 代码
```

每一层都确认没问题了，再往下查。

#### 原则 2：交叉验证，不轻易下结论

- git 说更新了 ≠ 真的更新了 → 去文件里搜关键词验证
- 服务状态是 running ≠ 功能正常 → curl 一下 API 试试
- 多找几个角度验证，才能确定问题在哪

#### 原则 3：一条路走不通就换一条

- git pull 不行 → 试试 curl 直接下载
- GitHub 访问慢 → 换国内 CDN（jsDelivr、fastgit 等）
- 不要死磕一种方法，灵活变通

---

### 9.4 验证生产模式是否生效的方法

更新完代码后，怎么确认 gzip 和缓存真的生效了？

**方法 1：看启动日志**
```bash
sudo journalctl -u improve-skills -n 10 --no-pager
```
- 有 `[PROD]` 和 `gzip compression and HTTP caching enabled` 就是生产模式

**方法 2：浏览器开发者工具（最准确）**
1. 按 F12 打开开发者工具
2. 切到 Network（网络）标签
3. 按 Ctrl+R 刷新页面
4. 点任意一个请求（比如 HTML 页面或 JS 文件）
5. 看 Response Headers 里有没有：
   - `Content-Encoding: gzip` → 压缩生效
   - `Cache-Control: public, max-age=...` → 缓存生效
