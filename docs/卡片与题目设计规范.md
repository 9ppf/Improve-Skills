# 卡片与题目设计规范（三科统一）

> 本文档是离散数学(02324)、数据结构与算法(13003)、计算机系统原理(13015)三科统一的知识框架与题库设计标准。
> 后续章节补充照此执行。各科差异见第八节「科目差异对照表」。

---

## 一、核心原则

1. **考核要求驱动**：每张概念卡的知识点必须能追溯到考核要求的某个条目
2. **覆盖率优先**：每个知识点至少被1道题目覆盖，覆盖率≥80%才能验收通过
3. **题型匹配层级**：识记/领会偏选择填空，简单应用偏计算，综合应用偏证明/简答/论述
4. **一章一章推进**：先把一章的闭环跑通做样板，确认没问题再扩展
5. **只改两个JSON**：补充知识点时只改知识框架JSON和题库JSON，页面代码不动

## 二、卡片设计规范

### 2.1 卡片类型

| 卡片类型 | cardType值 | 适用考核层级 | 内容特点 | 正面 | 背面 |
|---|---|---|---|---|---|
| 记忆卡 | `memory` | 识记 + 领会 | 定义、术语、概念、关系、性质、结构、分类 | 概念名+一句话总结 | 知识点列表 + 举例 + 考点 |
| 计算卡 | `calculation` | 简单应用 | 公式、步骤、地址计算、演算过程、求范式 | 概念名+一句话总结 | 公式/步骤 + 例题 + 考点 |

**综合应用不单独建卡**：综合应用属于能力而非固定知识点，放题库出题。

### 2.2 拆卡原则

| 规则 | 说明 |
|---|---|
| 每卡知识点数 | 3-7个，超过7个必须拆卡 |
| 拆卡依据 | 按考核层级拆（识记/领会→记忆卡，简单应用→计算卡），或按主题拆 |
| 同一考核主题 | 可拆成1张记忆卡+1张计算卡，分别覆盖领会层和应用层 |
| 不同考核主题 | 各自独立建卡，不合并 |
| 去重 | 拆卡时检查是否与其他卡有知识点重复，重复的只保留在一张卡中 |
| 旧题cardId重映射 | 拆卡后旧题的cardId必须重新映射到新卡 |

**离散数学专属拆卡规则**：

| 规则 | 说明 |
|---|---|
| 定律类拆卡 | 当一组定律超过7条时，按"基本定律→运算定律→高级定律"分层拆卡 |
| 推理规则类拆卡 | 当推理规则超过7条时，按"基本推理→高级推理"分层拆卡 |

### 2.3 卡片字段规范

```json
{
  "term": "概念名（与题库cardId完全一致）",
  "priority": "重点 | 一般 | 了解",
  "level": "识记 | 领会 | 理解 | 计算 | 应用 | 背诵",
  "summary": "一句话概括，不超过30字",
  "cardType": "memory | calculation",
  "points": ["知识点1", "知识点2", "..."],
  "ex": "具体举例，帮助理解",
  "exam": "考点提示：常考题型和注意事项",
  "hint": "记忆提示/口诀"
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| term | ✅ | 概念名，与题库cardId完全一致（含空格） |
| priority | ✅ | 重点(🔴)/一般(🟡)/了解(⚪) |
| level | ✅ | 计算/理解/背诵/应用 |
| summary | ✅ | 一句话，不超过30字 |
| cardType | ✅ | memory 或 calculation |
| points | ✅ | 3-7个知识点，每个一句话 |
| ex | ✅ | 具体举例，帮助理解 |
| exam | 推荐 | 考点提示 |
| hint | 推荐 | 记忆提示/口诀 |

### 2.4 知识点编写规范

- **一句话一个知识点**：不要把多个概念塞进一个点
- **按考核层级排列**：识记在前，领会在中，简单应用在后
- **可追溯**：每个知识点应对应考核要求中的某个条目
- **具体不抽象**：写"双重否定律：¬¬A ⇔ A"而不是"双重否定律"
- **公式要完整**：计算卡的知识点必须包含完整公式，不能只写名称
- **关键词具体**：关键词是题目匹配的依据，必须具体（如"MAR（主存地址寄存器）"而非"寄存器"）

## 三、题目设计规范

### 3.1 题目数量标准

| 规则 | 公式 | 说明 |
|---|---|---|
| 每卡最少题数 | `max(4, ⌈知识点数 × 0.7⌉)` | 知识点越多题越多 |
| 每知识点覆盖 | 至少1题 | 不允许有知识点0题覆盖 |
| 重点知识点 | 2题 | priority为重点(🔴)的知识点 |
| 综合应用题 | 每个考核主题1-2题 | 放题库，不绑卡 |

**计算示例**：
- 记忆卡6个知识点 → max(4, ⌈6×0.7⌉) = max(4, 5) = 5题
- 计算卡5个知识点 → max(4, ⌈5×0.7⌉) = max(4, 4) = 4题

### 3.2 题型分配规范

#### 记忆卡（识记+领会层）

| 题型 | 占比 | 说明 |
|---|---|---|
| 选择题(choice) | 40% | 偏识记层 |
| 填空题(fill) | 40% | 偏领会层 |
| 简答题(shortAnswer) | 20% | 偏理解层 |

#### 计算卡（简单应用层）

| 题型 | 占比 | 说明 |
|---|---|---|
| 计算题(calculate) | 40% | 核心计算能力 |
| 填空题(fill) | 30% | 公式/步骤填空 |
| 简答题(shortAnswer) | 30% | 步骤描述 |

> **计算机系统原理差异**：计算卡分配为 选择20%+填空30%+简答20%+计算30%，偏应用层

#### 综合应用题（放题库，不绑卡）

| 科目 | 题型1 | 占比 | 题型2 | 占比 |
|---|---|---|---|---|
| 离散数学 | proof（证明题） | 60% | shortAnswer | 40% |
| 数据结构与算法 | shortAnswer | 60% | essay（论述题） | 40% |
| 计算机系统原理 | shortAnswer | 60% | calculate | 40% |

### 3.3 题型名称规范

**必须使用以下标准名称，禁止缩写**：

| 正确名称 | 错误名称 | 说明 |
|---|---|---|
| `choice` | - | 选择题 |
| `fill` | - | 填空题（必须有 blanks 字段） |
| `shortAnswer` | ~~short~~ ❌ | 简答题 |
| `calculate` | ~~calc~~ ❌ | 计算题 |
| `proof` | - | 证明题（离散数学综合应用） |
| `essay` | - | 论述题（数据结构综合应用） |

### 3.4 题目字段规范

```json
{
  "id": "q-{科目码}-XXX",
  "type": "choice | fill | calculate | shortAnswer | proof | essay",
  "question": "题干",
  "options": ["A. ...", "B. ...", "C. ...", "D. ..."],
  "answer": "选项字母 | 文本答案 | 证明过程",
  "blanks": [{"answer": "答案", "synonyms": ["别名1", "别名2"]}],
  "chapter": "第N章 章名",
  "cardId": "与概念卡term完全一致（含空格）",
  "src": "ai | textbook",
  "explanation": "解析：为什么选B"
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| id | ✅ | 格式 `q-{科目码}-XXX`，递增（02324/13003/13015） |
| type | ✅ | choice/fill/calculate/shortAnswer/proof/essay |
| question | ✅ | 题干 |
| answer | ✅ | 选择题填选项字母，证明题填完整证明过程 |
| options | choice必填 | 4个选项，带A./B./C./D.前缀 |
| blanks | fill必填 | 数组，每个blank含answer和synonyms |
| chapter | ✅ | 格式 `第N章 章名`，与知识框架一致 |
| cardId | ✅ | 与概念卡term完全一致（含空格） |
| src | ✅ | ai(AI生成) 或 textbook(教材原题) |
| explanation | 推荐 | 答案解析 |

### 3.5 填空题规范

- 必须有 `blanks` 数组
- 每个 `___` 对应一个 blank 对象
- blank 必须有 `answer`，可选 `synonyms`
- synonyms 覆盖常见等价表述（如 `¬` 和 `!` 和 `非`）

### 3.6 证明题规范（离散数学专属）

```json
{
  "id": "q-02324-150",
  "type": "proof",
  "question": "证明：(A→B)∧(A→¬B) ⇔ ¬A（归谬律）",
  "answer": "证明：\n(A→B)∧(A→¬B)\n⇔ (¬A∨B)∧(¬A∨¬B) （蕴涵等值式）\n⇔ ¬A∨(B∧¬B) （分配律）\n⇔ ¬A∨F （否定律）\n⇔ ¬A （同一律）\n证毕。",
  "chapter": "第1章 命题与命题公式",
  "cardId": "蕴涵与等价等值式",
  "src": "ai",
  "explanation": "归谬律证明：蕴涵等值式+分配律+否定律+同一律"
}
```

| 规范 | 说明 |
|---|---|
| answer格式 | 分步骤写，每步标注所用定律/规则 |
| 步骤分隔 | 用换行符 `\n` 分隔步骤 |
| 最后一步 | 必须有"证毕"或"Q.E.D."标记 |
| keywords | 可选，用于自动评分时的关键词匹配 |

### 3.7 覆盖率匹配规则

- 题目的 `question + explanation + answer` 合并后搜索知识点关键词
- 关键词从知识点文本中提取（按标点分割，取2字以上片段）
- **建议**：题目 explanation 中直接引用知识点原文，确保匹配

### 3.8 题目质量要求

- **不重复**：同一知识点不要出两道几乎一样的题
- **题型多样**：每张卡至少覆盖2种题型
- **选项规范**：选择题4个选项，干扰项要有合理性，不能有明显错误
- **简答规范**：参考答案分点列出，不超过5个要点
- **证明规范**：每步必须标注依据定律，步骤完整可追溯
- **符号一致**：离散数学使用标准逻辑符号（¬ ∧ ∨ → ↔ ⇔ ∀ ∃），不用编程符号；数据结构可用代码/伪代码

## 四、考核要求对照规范

### 4.1 考核要求section格式

每章必须在核心概念section前插入考核要求section：

```json
{
  "type": "考核知识点与考核要求",
  "items": [
    {
      "topic": "考核主题名",
      "levels": [
        {"level": "识记", "content": "具体识记条目，分号分隔"},
        {"level": "领会", "content": "具体领会条目"},
        {"level": "简单应用", "content": "具体应用条目"},
        {"level": "综合应用", "content": "综合应用条目"}
      ]
    }
  ]
}
```

### 4.2 考核层级→卡片→题目映射表

每章补充完成后，必须填写映射表验证覆盖率：

| 考核主题 | 层级 | 条目 | 对应卡片 | 对应题目 | 状态 |
|---|---|---|---|---|---|
| 主题1 | 识记 | 具体条目 | 卡片A | q-XXXX-001~003 | ✅ |
| 主题1 | 领会 | 具体条目 | 卡片A | q-XXXX-004 | ✅ |
| 主题1 | 简单应用 | 具体条目 | 卡片B | q-XXXX-008 | ✅ |
| 主题1 | 综合应用 | 具体条目 | (题库) | q-XXXX-012 | ✅ |

## 五、执行流程（6步标准流程）

### Step 1：提取考核要求
- 从PDF考核大纲提取每章的考核主题和层级
- 写入知识框架JSON的"考核知识点与考核要求"section
- 确保每个考核主题的每个层级都有具体条目

### Step 2：评估现有概念卡
- 逐卡检查：知识点数（3-7）、题数、覆盖率、题型
- 列出未覆盖知识点清单
- 列出需拆卡清单（>7点）

### Step 3：拆卡与建卡
- 按拆卡原则（每卡3-7点）拆分或新建概念卡
- 记忆卡（识记+领会）和计算卡（简单应用）分开
- 离散数学：定律/规则类按层次拆分（基本→运算→高级）
- 综合应用不建卡
- 拆卡后重新映射旧题cardId
- 检查去重

### Step 4：出题
- 按题目数量标准计算每卡题数
- 按题型分配规范确定题型比例
- 确保每个知识点至少1题覆盖
- 综合应用按每主题1-2题放题库
- 计算卡必须有calculate类型题目
- 离散数学：综合应用以proof为主，证明题answer必须分步骤、标注定律依据

### Step 5：修题型名+验收
- 全章扫描 `short`→`shortAnswer`、`calc`→`calculate`
- 检查填空题是否有 blanks
- 运行检查清单（见第六节）
- 填写考核要求→卡片→题目映射表
- 浏览器验证页面显示正常

### Step 6：版本更新
- 更新self-study.json中该科目的v参数
- 运行build.py构建

## 七、常见错误与防范

| 错误 | 后果 | 防范 |
|---|---|---|
| 知识点超过7个不拆卡 | 卡片臃肿，题目无法覆盖 | 拆卡原则：每卡3-7点 |
| 定律/规则超过7条不拆卡（离散数学） | 覆盖率低，题数不足 | 按层次拆卡：基本→运算→高级 |
| cardId与term不一致（含空格） | 题目无法匹配到卡片 | 复制粘贴term，不手动输入 |
| 综合应用建成卡片 | 正反面不好设计，无法自测 | 综合应用只放题库 |
| 全出选择题 | 无法覆盖简单应用和综合应用 | 题型分配规范：计算卡40%计算题 |
| 知识点无题目覆盖 | 学习闭环断裂 | 覆盖率检查：每点至少1题 |
| 填空题缺blanks字段 | 页面渲染崩溃 | fill题必须有blanks数组 |
| 题型名用缩写(calc/short) | 题型无法识别 | 用标准名：calculate/shortAnswer |
| 证明题无步骤标注（离散数学） | 无法评分，学习效果差 | 每步标注定律依据，最后写证毕 |
| 拆卡后知识点重复 | 背诵卡重复显示 | 拆卡时去重，只保留在一张卡中 |
| 拆卡后旧题cardId未更新 | 题目找不到对应卡片 | 拆卡后批量重新映射cardId |
| 拆卡后新卡0题 | 闭环断裂 | 拆卡时同步分配旧题+补新题 |
| 覆盖率匹配关键词太短 | 匹配失败 | 关键词≥2字，优先用专有名词 |
| 一章只建卡不出题 | 闭环断裂 | 建卡和出题同步进行 |

## 八、科目差异对照表

| 维度 | 离散数学(02324) | 数据结构与算法(13003) | 计算机系统原理(13015) |
|---|---|---|---|
| 综合应用题型 | **proof**（证明题）60% + shortAnswer 40% | shortAnswer 60% + **essay**（论述题）40% | shortAnswer 60% + calculate 40% |

| 符号系统 | ¬ ∧ ∨ → ↔ ⇔ ∀ ∃ | 代码/伪代码 | 代码/伪代码 |
| 知识点特点 | 偏理论，定义+定理+证明 | 偏实践，概念+操作+实现 | 偏系统，概念+结构+原理 |
