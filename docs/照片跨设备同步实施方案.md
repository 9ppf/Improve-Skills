# 拍照答案跨设备同步 — 实施方案

## 一、需求

手机拍照做计算题/证明题 → 上传云端 → 电脑打开同一页面查看照片，方便后期总结。

## 二、技术架构

```
手机浏览器                         电脑浏览器
    │                                  │
    │ POST /api/quiz-photo             │ GET /api/quiz-photos?subject=xxx
    │ {subject, questionId, dataURL}   │
    ▼                                  ▼
┌──────────────────────────────────────────┐
│           dev_server.py (Python)          │
│                                           │
│   /api/quiz-photo   POST  上传单张照片     │
│   /api/quiz-photos  GET   拉取科目全部照片 │
│                                           │
│   存储: data/quiz-photos-{subject}.json   │
│   格式: { "questionId": "dataURL", ... }  │
└──────────────────────────────────────────┘
```

## 三、代码改动清单

### 3.1 服务端 `dev_server.py`

新增两个 API 端点：

| 方法 | 路径 | 请求 | 响应 | 存储文件 |
|------|------|------|------|----------|
| POST | `/api/quiz-photo` | `{subject, questionId, dataURL}` | `{status: "ok"}` | `data/quiz-photos-{subject}.json` |
| GET | `/api/quiz-photos?subject=xxx` | — | `{questionId: dataURL, ...}` | 同上 |

- 使用 `_file_lock` 线程锁防并发写入冲突（与 quiz-records 一致）
- 使用 `atomic_write_json` 原子写入 + 重试机制
- 使用 `_load_json_backup_on_corrupt` 损坏文件自动备份

### 3.2 前端 `js/自考学习/练习测验.js`

| 函数 | 作用 |
|------|------|
| `uploadPhotoToServer(qId, dataURL)` | 拍照后异步上传，先写本地待同步队列，再发请求 |
| `getPendingPhotos()` / `setPendingPhotos(arr)` | 照片待同步队列（localStorage 兜底） |
| `flushPendingPhotos()` | 批量重传失败的照片（与 flushPendingRecords 同模式） |
| `syncPhotosFromServer()` | 页面加载时从服务端拉取全部照片，合并到本地缓存 |

同步流程：
1. **拍照时**：压缩 → 存 localStorage → 异步上传服务端 → 失败则进待同步队列
2. **页面加载时**：先重传待同步队列 → 再从服务端拉取全部照片 → 合并到本地 → 重新渲染
3. **自动同步**：每 15 秒检查待同步队列，有则自动重传
4. **页面切回前台**：visibilitychange 事件触发即时同步

### 3.3 移动端拍照优化

文件输入添加 `capture="environment"` 属性：
```html
<input type="file" accept="image/*" capture="environment" ...>
```
- 手机端直接打开后摄像头，无需选择「相册/拍照」
- 桌面端忽略该属性，行为不变

## 四、部署步骤

### 4.1 准备工作
1. 确保 `.env` 在 `.gitignore` 中（防止密钥泄露）
2. 确认 `data/` 目录在 `.gitignore` 中（防止用户数据泄露）

### 4.2 部署到 Render

1. 将项目推送到 GitHub
2. 注册 [render.com](https://render.com)
3. New → Web Service → 连接 GitHub 仓库
4. 配置：
   - **Runtime**: Python 3
   - **Build Command**: `pip install watchdog`
   - **Start Command**: `python dev_server.py --port $PORT --no-build`
   - **Environment Variables**:
     - `DEEPSEEK_API_KEY` = 你的密钥（只在这里配，不写进代码）
5. 部署完成后获得 `https://your-app.onrender.com` 链接
6. 手机和电脑都打开这个链接即可

### 4.3 验证
- 手机打开练习测验页 → 拍照提交 → 确认照片显示
- 电脑打开同一页面 → 确认能看到手机拍的照片
- 断网拍照 → 恢复网络 → 确认自动补同步

## 五、安全防护说明

> ⚠️ 当前实现为**个人使用**场景，安全措施较轻。
> 如需**多人使用**，必须补充以下防护。

### 5.1 当前安全状态（个人使用）

| 防护项 | 当前状态 | 说明 |
|--------|----------|------|
| API 密钥 | ✅ 安全 | 通过环境变量配置，前端不接触密钥 |
| CORS | ⚠️ `*` 通配 | 允许任意域名访问 API |
| 认证 | ❌ 无 | 任何人知道 URL 即可调用接口 |
| 速率限制 | ❌ 无 | 可被无限调用产生费用 |
| 数据隔离 | ❌ 无 | 所有用户共享同一数据文件 |
| 上传限制 | ❌ 无 | 无文件大小/频率限制 |

### 5.2 多人使用必须补充的防护

#### 1. 用户认证（必须）
```python
# 方案：简单的 Bearer Token 认证
def _check_auth(self):
    token = self.headers.get('Authorization', '')
    expected = 'Bearer ' + os.environ.get('ACCESS_TOKEN', '')
    return token == expected

# 在每个 API handler 开头加入：
if not self._check_auth():
    self._send_json(401, {'error': 'Unauthorized'})
    return
```
- 每个用户分配独立的 `ACCESS_TOKEN`
- 前端请求时携带 `Authorization: Bearer xxx`

#### 2. CORS 域名白名单（必须）
```python
# 替换 Access-Control-Allow-Origin: * 为指定域名
ALLOWED_ORIGINS = ['https://your-app.onrender.com']
origin = self.headers.get('Origin', '')
if origin in ALLOWED_ORIGINS:
    self.send_header('Access-Control-Allow-Origin', origin)
```

#### 3. 速率限制（必须）
```python
# 防止 API 被滥用产生费用
from collections import defaultdict, deque
import time

_rate_limiter = defaultdict(lambda: deque(maxlen=20))

def _check_rate_limit(self, key='default', max_per_min=10):
    now = time.time()
    dq = _rate_limiter[key]
    while dq and now - dq[0] > 60:
        dq.popleft()
    if len(dq) >= max_per_min:
        return False
    dq.append(now)
    return True
```
- AI 对话接口：每用户每分钟 10 次
- 照片上传接口：每用户每分钟 5 次

#### 4. 数据隔离（必须）
```python
# 按用户 ID 隔离数据
filename = f'quiz-photos-{subject}-{user_id}.json'
# 或使用数据库替代 JSON 文件
```
- 每个用户的照片、答题记录独立存储
- 推荐迁移到 SQLite 或 PostgreSQL

#### 5. 上传安全（必须）
```python
# 限制上传大小（防止恶意大文件）
MAX_PHOTO_SIZE = 200 * 1024  # 200KB

# 验证 dataURL 格式（防止注入）
if not data_url.startswith('data:image/jpeg;base64,'):
    self._send_json(400, {'error': 'Only JPEG images allowed'})
    return

# 限制每科目照片总数
if len(photos) >= 500:
    self._send_json(400, {'error': 'Photo limit reached'})
    return
```

#### 6. 内容安全（推荐）
- 对 AI 对话内容进行敏感词过滤
- 照片上传后检查是否包含违规内容

#### 7. HTTPS 强制（推荐）
- Render 默认提供 HTTPS，但应设置 HSTS 头
- 禁止 HTTP 访问

### 5.3 安全升级优先级

| 优先级 | 防护项 | 不做的风险 |
|--------|--------|------------|
| P0 | 用户认证 | 任何人可调用你的 AI 接口产生费用 |
| P0 | CORS 白名单 | 任意网站可跨域调用你的 API |
| P0 | 速率限制 | 恶意调用导致账单暴涨 |
| P1 | 数据隔离 | 用户数据互相泄露 |
| P1 | 上传限制 | 大文件撑满磁盘 / 注入攻击 |
| P2 | 内容安全 | 违规内容上传 |
| P2 | HTTPS 强制 | 中间人攻击窃听数据 |

## 六、存储容量评估

| 项目 | 单张大小 | 每科目上限 | 总容量 |
|------|----------|------------|--------|
| 压缩后照片 | ~50-100KB | ~50 张 | ~5MB |
| JSON 开销 | — | — | ~10MB/科目 |

- 3 个科目总共 ~30MB，单文件存储完全可行
- 如超过 100 张/科目，建议迁移到对象存储（如 Cloudflare R2、AWS S3）

## 七、离线降级策略

| 场景 | 行为 |
|------|------|
| 拍照时无网络 | 照片存 localStorage + 进入待同步队列 |
| 页面加载时无网络 | 只显示 localStorage 中的照片 |
| 恢复网络 | 自动重传待同步照片（15 秒检查 / 页面切回前台时立即检查） |
| 服务端不可用 | 静默失败，不影响本地使用体验 |
