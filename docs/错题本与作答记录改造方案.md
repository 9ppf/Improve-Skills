## 一、要解决的问题

错题这件事现在没有独立的落点，四条问题互相纠缠。

错题没有独立存储。真题练习页的「标记错题」写的是 localStorage 的 `exam-training-data`，全项目只有 `真题练习.js` 自己读写；题库管理和复盘总结认定的错题来自 `quiz-records` 里 `isCorrect === false` 的记录。前者是手动状态，后者是答题产物，两套判定互不相通，数字也不可能对上。

同一道题会出现两个相反的判定。记录落库时用的是 `score >= total`，即满分才算对；界面上判定用 `getLevel()`，达到阈值就算已掌握。一道三空的填空题答对两空，`isCorrect` 为 false 而等级为 `mastered`，题库管理把它算作错题、练习测验把它算作已做对。

重做能力缺失。`/api/quiz-records` 写入时按 `questionId` 去重覆盖，同一道题重做多少次，文件里也只留最近一条。

自评不落库。`selfEval()` 只改内存里的 `selfOverride`，既没调 `saveQuizRecord()`，`results` 也没写 localStorage。刷新即失，复盘总结始终不知道你自评过。

## 三、设计原则

**先立契约再建数据。** 两份题库的 schema 不一致，这才是耦合的根源。定义一份规范题目 schema，错题本只依赖这份契约，不必认识题库内部的字段写法；题库和真题各自往契约上收敛，属于可以分批做的独立工作。

错题本要自包含。每条错题带一份契约格式的题目快照，渲染和判分不依赖外部文件，同时保留 `sourceId` 与 `syncedAt`，让「题库已更新而快照还是旧版」这种情况可被检测。

能自动判分的自动判分，不能的走自评，两种结果都落库。自评与自动判定用同一张表记录，靠 `gradedBy` 字段区分来源。

存量回填与增量入本共用同一套写入函数，避免两批数据的格式漂移。

## 四、规范题目 schema

这份 schema 目前只服务错题本与新的答题记录，不改动现有 `quiz-bank-*.json` 和 `exam-data-*.js`，把风险隔离在新增数据里。

| 字段 | 说明 |
|---|---|
| `canonicalId` | 规范 id，格式 `{来源}-{科目}-{原id}`，如 `qb-13015-034`、`exam-13015-012` |
| `source` | `quiz-bank`、`exam-data`、`ai-practice` 三选一 |
| `sourceId` | 来源文件里的原始 id |
| `syncedAt` | 快照生成时间，ISO 字符串 |
| `type` | 规范题型枚举：`choice`、`multi`、`judge`、`fill`、`calculate`、`shortAnswer`、`essay`、`proof` |
| `typeLabel` | 中文显示名 |
| `stem` | 题干 |
| `options` | 选项数组，非选择题为 null |
| `blanks` | `[{ answer, synonyms, hint }]`，无结构时为 null |
| `points` | `[{ point, synonyms, weight }]`，无结构时为 null |
| `steps` | `[{ desc, keywords, hint }]`，无结构时为 null |
| `answer` | 参考答案 |
| `answerAliases` | 计算题可接受的等价答案 |
| `explanation` | 解析 |
| `chapter` | 规范章节名，如「第2章 数据的表示和运算」 |
| `chapterNo` | 章号，整数 |
| `kp` | 知识点，取自原 `cardId` |

真题的填空题答案是 `"程序；数据"` 这种字符串，没有空位索引。要让它进入契约，回填时需要按题干里的下划线数量拆分并逐题核对，无法自动完成的部分标记为 `blanks: null` 并降级为自评。

## 五、错题本数据结构

新增 `data/wrong-book-{科目}.json`，一个科目一个文件。

```
{
  entryId,                        // 主键，如 wb-13015-0001
  questionRef: { source, sourceId, canonicalId },
  snapshot: { ...规范题目 schema... },
  status: 'open' | 'solved',
  firstWrongAt,                   // ISO
  lastAttemptAt,                  // ISO
  solvedAt,                       // ISO 或 null
  attempts: [
    { n, at, userAnswer, score, total, isCorrect, level, wrongReason, gradedBy, details }
  ],
  flags: []                       // 异常标记，如 判分结构缺失
}
```

`attempts` 是追加式的，`n` 从 1 开始递增。`gradedBy` 取 `auto` 或 `self`。`flags` 用来记录「自动判分缺失」这类需要人工介入的状态。

接口沿用现有风格，新增两个路由：`GET /api/wrong-book?subject=` 读全量，`POST /api/wrong-book` 写单条（新增或追加 attempt）。写入用与 `_handle_save_ai_practice` 相同的原子写与文件锁保护。

## 六、存量回填

回填是派生操作，输入是现有的 `quiz-records-*.json`，输出是错题本三个文件。

入本判定用 `isCorrect === false`，得到 207 条。因为现在每道题只有一条记录，去重后就是 207 道题，每题入本一次。

`firstWrongAt` 只能取现有记录的那一个 timestamp，回填时把 23 条 Unix 秒和 436 条 ISO 字符串统一成同一种格式。`attempts` 回填后长度是 1，等重做才会变成 2。

`status` 初始为 `open`，除非能从 localStorage 的 `ss_bank_solved_{科目}` 找到对应的已解决标记并迁移过来。这份 localStorage 不在三个 json 里，目前没有读到内容，需要确认是否迁移。

13003 那 3 道缺 `blanks` 的填空题照常入本，打上「判分结构缺失」标记，重做时走自评。

122 条手写的答错原因挂到对应条目的第一条 attempt 上，条数不变。

回填过程需要先备份原记录文件，跑完输出一份报告，写明入本多少条、异常多少条、跳过多少条。判对的 252 条记录不进错题本，但正确率和已答题数还要用，原样保留。

## 七、增量入本

每次答题写记录时，如果 `isCorrect === false`：错题本里没有这道题就新增条目，已有条目则追加一条 attempt 并把 `status` 置回 `open`。如果 `isCorrect === true` 且该题已在错题本里，把 `status` 改成 `solved` 并写上 `solvedAt`，条目保留不删。

按这个规则，错题本会累积历史，已攻克的题也能回看。

## 八、重做与作答历史

重做走的是同一套判分函数，按题型的结构完整度分流：

| 题型 | 判分方式 |
|---|---|
| 选择、选择多选、判断 | 自动，选项集合比对 |
| 计算 | 自动，数值字符串匹配加 `answerAliases` |
| 填空（有 `blanks`） | 自动，逐空比对，支持同义词与无序匹配 |
| 简答、论述（有 `points`） | 自动，按要点权重计分 |
| 证明（有 `steps`） | 自动，按步骤关键词计分 |
| 上述题型缺少对应结构 | 自评，结果落库并标记 `gradedBy: self` |

判定口径要统一。落库的 `isCorrect` 与界面展示的等级必须来自同一个函数，建议以「是否达到该题通过阈值」为唯一标准，`isCorrect` 与 `level === 'mastered'` 永远等价，消除满分才算对与到阈值算掌握之间的分歧。

前端要把「每题一个结果」的索引改成「取最近一次、可展开历史」。练习测验里读 `results[questionId]` 的地方有 38 处，这是本次改动中工作量最集中的一块。

## 九、复盘总结换源

三处读取要一起改，否则数字会互相矛盾：

| 位置 | 现在读什么 | 改成 |
|---|---|---|
| 章节卡统计（`getChapterQuizStats`） | `quizRecords` 按 `r.chapter` 模糊匹配 | 错题本条目按 `snapshot.chapterNo` 归章 |
| 概念统计（`buildConceptStats`） | `quizRecords` 经 `quizBank` 映射到 `cardId` | 错题本条目直接读 `snapshot.kp` |
| 题库管理错题筛选 | `quizBank` 加 `rec.isCorrect` | 错题本条目，`status === 'open'` 为待解决、`solved` 为已解决 |

题库管理的题卡渲染要就地扩展：现在展开后显示答案、解析、我的答案、答错原因输入框，改造后要在这块加作答历史列表，每次重做一条。这是唯一必须改动现有面板的地方，因为作答历史和题目正文属于同一张卡片的信息层级，另开一个面板反而割裂。

已解决标记 `ss_bank_solved_{科目}` 迁移到错题本 `status` 之后，那份 localStorage 可以废弃。

## 十、需要一并修复的既有缺陷

`tsToMs()` 改成同时接受毫秒数字、Unix 秒和 ISO 字符串，这是回填和「取最近一次」都依赖的基础。

250 道缺 `points` 的简答论述题有三个处理方向，需要在实施前定一个：补齐 `points` 内容（工作量大但根治）；把无 `points` 的题改成只能自评（纯代码改动，不动内容）；暂时把这类题从练习池排除。选择不同，练习测验的题目数量和正确率统计口径都会变。

70 道缺 `blanks` 的 13003 填空题同样是三选一：按 `answer` 拆成单空结构（这批题题干只有一个下划线、答案也是单值，可以批量处理）；改成自评；暂时排除。

## 十一、实施顺序与验收标准

分四步，每步独立验收，互不阻塞。

### 第一步 回填错题本

不改任何现有页面的读取逻辑，风险最低。

- 回填脚本生成 `data/wrong-book-{科目}.json`，条目数 13015 是 120、13003 是 41、02324 是 46
- 每条含 `questionRef`、契约格式 `snapshot`、`status`、`firstWrongAt`、长度为 1 的 `attempts`
- 122 条答错原因全部挂到对应条目的 attempt 上，条数不变
- 3 条判分结构缺失的题带上异常标记
- 输出回填报告，原记录文件先备份，回填后记录仍是 459 条

### 第二步 打通重做

- `GET/POST /api/wrong-book` 就绪，写入是追加式
- 错题页可重复答题，每次提交追加一条 attempt
- 选择、计算、填空自动判定；缺结构的题走自评且落库
- `tsToMs` 三种时间格式都能解析
- 练习测验的 38 处结果索引改成取最近一次，历史可展开

### 第三步 统一判定口径

- `isCorrect` 与 `level === 'mastered'` 由同一个函数产出，两者永远等价
- 拿三空填空答对两空这类题实测，复盘总结与练习测验的判定一致
- 自评结果刷新后仍在，复盘总结能读到

### 第四步 复盘总结换源

- 章节卡统计、概念统计、题库管理错题筛选三处全部改读错题本
- 复盘总结的错题数与题库管理一致
- 已解决标记迁移完成，localStorage 那份废弃
- 现有 207 道错题、459 条记录、122 条答错原因一条不丢
