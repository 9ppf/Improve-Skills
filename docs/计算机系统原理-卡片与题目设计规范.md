# 计算机系统原理 — 卡片与题目设计规范

> 基于第1章验收经验总结，后续章节（2-7章）照此执行。
> 对标《离散数学学习闭环标准模板》和《离散数学-卡片与题目设计规范》。

---

## 一、核心原则

1. **考核要求驱动**：每个概念卡的知识点必须对应考核要求中的某条，不能凭感觉建卡
2. **覆盖率优先**：每个知识点至少有1道题覆盖，覆盖率≥80%才能验收通过
3. **题型匹配层级**：记忆卡偏选择+填空，计算卡偏计算+填空，综合应用偏简答
4. **一章一章推**：先跑通一章的闭环做样板，确认没问题再扩展
5. **只改两个JSON**：补充知识点时只改知识框架JSON和题库JSON，不动页面代码

## 二、卡片设计规范

### 2.1 卡片类型

| 卡片类型 | cardType | 考核层级 | 适用内容 |
|---|---|---|---|
| 记忆卡 | `memory` | 识记+领会 | 定义、术语、概念、结构、分类 |
| 计算卡 | `calculation` | 简单应用+综合应用 | 公式计算、地址计算、范围推导、结果分析 |

### 2.2 拆卡原则

- **每卡知识点 3-7 个**，超过 7 必须拆
- 拆卡方向：按考核主题拆、按识记/应用拆、按概念粒度拆
- 拆卡后旧题的 cardId 必须重新映射到新卡

### 2.3 第1章拆卡实例

| 原卡 | 原点数 | 拆成 | 新卡点数 |
|---|---|---|---|
| CPU与硬件组成 | 12 | CPU核心部件(6) + 存储与I/O系统(6) | 12 |
| 程序语言分类与翻译程序 | 11 | 程序语言分类(5) + 翻译程序与执行方式(6) | 11 |
| 程序开发与运行过程 | 13 | 程序开发流程(7) + 程序运行环境(6) | 13 |
| 计算机系统层次结构 | 12 | 层次结构模型(6) + 硬件与软件关系(6) | 12 |
| 系统软件与应用软件 | 8 | 系统软件(4) + 应用软件与语言处理程序(4) | 8 |
| 用户视角与课程定位 | 8 | 不同用户视角(4) + 课程定位与透明性(4) | 8 |
| 性能影响因素 | 11 | 性能影响因素(6) + 性能综合分析(5) | 11 |

### 2.4 字段规范

```json
{
  "term": "卡片名（与题库cardId完全一致）",
  "cardType": "memory | calculation",
  "priority": "重点 | 一般 | 了解",
  "level": "识记 | 领会 | 理解 | 计算 | 应用 | 背诵",
  "summary": "一句话概括",
  "points": ["知识点1", "知识点2", ...],
  "ex": "举例",
  "exam": "考点提示",
  "hint": "记忆提示"
}
```

### 2.5 知识点编写规范

- 每个知识点一句话，含"关键词：内容"格式
- 关键词是题目匹配的依据，必须具体（如"MAR（主存地址寄存器）"而非"寄存器"）
- 知识点之间不重复，同一概念不跨卡重复

## 三、题目设计规范

### 3.1 数量标准

| 卡片类型 | 标准题数 | 最少题数 | 说明 |
|---|---|---|---|
| 记忆卡 | max(4, ⌈n×0.7⌉) | 4 | n=知识点数 |
| 计算卡 | max(4, ⌈n×0.7⌉) | 4 | 同上 |
| 综合应用 | 每考核主题1-2题 | - | 不单独建卡，放题库 |

### 3.2 题型分配

| 卡片类型 | 选择 | 填空 | 简答 | 计算 | 说明 |
|---|---|---|---|---|---|
| 记忆卡 | 40% | 40% | 20% | - | 偏识记层 |
| 计算卡 | 20% | 30% | 20% | 30% | 偏应用层 |
| 综合应用 | - | - | 60% | 40% | 简答含分析题 |

### 3.3 题型名称规范

**必须使用以下标准名称，禁止缩写**：

| 正确名称 | 错误名称 | 说明 |
|---|---|---|
| `choice` | - | 选择题 |
| `fill` | - | 填空题（必须有 blanks 字段） |
| `shortAnswer` | ~~short~~ ❌ | 简答题 |
| `calculate` | ~~calc~~ ❌ | 计算题 |
| `proof` | - | 证明题（如有） |
| `essay` | - | 论述题（如有） |

### 3.4 字段规范

```json
{
  "id": "q-13015-XXX",
  "type": "choice | fill | shortAnswer | calculate | proof | essay",
  "question": "题干",
  "chapter": "第N章 章节名",
  "cardId": "必须与知识框架的term完全一致",
  "src": "ai",
  "explanation": "解析（包含知识点关键词，确保覆盖率匹配）",
  "options": ["A. ...", "B. ...", "C. ...", "D. ..."],
  "answer": "A | 文本答案",
  "blanks": [{"answer": "答案", "synonyms": ["同义词"]}]
}
```

### 3.5 填空题规范

- 必须有 `blanks` 数组
- 每个 `___` 对应一个 blank 对象
- blank 必须有 `answer`，可选 `synonyms`

### 3.6 覆盖率匹配规则

- 题目的 `question + explanation + answer` 合并后搜索知识点关键词
- 关键词从知识点文本中提取（按标点分割，取2字以上片段）
- **建议**：题目 explanation 中直接引用知识点原文，确保匹配

## 四、考核要求对照规范

### 4.1 考核要求section格式

```json
{
  "type": "考核知识点与考核要求",
  "items": [
    {
      "topic": "考核主题名",
      "levels": [
        {"level": "识记", "content": "具体要求内容"},
        {"level": "领会", "content": "..."},
        {"level": "简单应用", "content": "..."},
        {"level": "综合应用", "content": "..."}
      ]
    }
  ]
}
```

### 4.2 映射表格式

| 考核主题 | 层级 | 对应概念卡 | 题目数 |
|---|---|---|---|
| 主题1 | 识记 | 卡片A | N |
| 主题1 | 领会 | 卡片A、卡片B | N |
| 主题1 | 简单应用 | 卡片C | N |

## 五、执行流程（6步标准流程）

### 第1步：提取考核要求
- 从PDF考核大纲提取每章的考核主题和层级
- 写入知识框架JSON的"考核知识点与考核要求"section

### 第2步：评估现有概念卡
- 逐卡检查：知识点数（3-7）、题数、覆盖率、题型
- 列出未覆盖知识点清单
- 列出需拆卡清单（>7点）

### 第3步：拆卡/扩充
- 按2.2拆卡原则执行
- 拆卡后重新映射旧题cardId
- 补充知识点内容

### 第4步：补题
- 按3.1数量标准计算每卡题数
- 按3.2题型分配出题
- 确保每个知识点至少1题覆盖
- 计算卡必须有calculate题

### 第5步：修题型名
- 全章扫描 `short`→`shortAnswer`、`calc`→`calculate`
- 检查填空题是否有 blanks

### 第6步：验收
- 运行检查清单（见第六节）
- 浏览器验证页面显示正常
- 更新版本号

## 八、常见错误与防范

| # | 错误 | 防范 |
|---|---|---|
| 1 | 题型名用缩写(short/calc) | 只用标准全名(shortAnswer/calculate) |
| 2 | 知识点超7不拆 | 超7必须拆，按考核主题分 |
| 3 | 拆卡后旧题cardId未更新 | 拆卡后批量重新映射cardId |
| 4 | 填空题缺blanks | 每个fill题必须有blanks数组 |
| 5 | 题目不覆盖知识点 | explanation中引用知识点原文 |
| 6 | 计算卡无calculate题 | 计算卡必须至少1道calculate |
| 7 | cardId与term不一致 | 拷贝term作为cardId，不手打 |
| 8 | 拆卡后新卡0题 | 拆卡时同步分配旧题+补新题 |
| 9 | 覆盖率匹配关键词太短 | 关键词≥2字，优先用专有名词 |
| 10 | 1张卡只有1种题型 | 每卡至少2种题型，记忆卡=选择+填空 |
