# 组件文件路由规范

## 触发条件

当任务涉及以下任一操作时调用本 Skill：

- 创建新文件或新文件夹
- 保存生成的 HTML / JSON / 图片 / 文档
- 放置临时脚本、调试输出或草稿
- 创建备份或归档
- 不确定某个文件应该放在哪里

## 核心原则

1. **最终交付物 → `e:\TraeWorkToDo\Workbench`**
2. **中间产物 → `e:\TraeWorkToDo\temp\{模块}\{任务}`**（目录名固定为 `temp`，禁止使用 `tmp` 或其他变体）
3. **支撑资源 → 与最终交付物同目录，或放入 `assets/` 子目录**
4. **禁止在 `e:\TraeWorkToDo\Workbench` 之下创建 `中间产物`、`tmp`、`temp`、`demo` 等子目录存放非交付物——中间产物只能放在根目录的 `temp/` 下**
5. **Skill / 基础设施文件除外，可位于 `.trae/skills/`**
6. **每次创建/迁移文件前必须调用本 Skill 做路由判断，不能凭直觉决定文件位置**

> 工作台按模块划分。当前已有模块：`自考学习`、`阅读`。后续新增模块按相同结构扩展。

## 决策流程

每次收到保存/创建请求时，按以下顺序判断：

```
收到保存/创建请求
  │
  ▼
是 Skill / 基础设施文件？
  ├─ 是 → 保存到 .trae/skills/ 或对应基础设施位置
  └─ 否 → 继续
       │
       ▼
是最终交付物？
  ├─ 否 → 保存到 temp\{模块}\{任务}\
  └─ 是 → 继续
       │
       ▼
定位工作台模块
  │
  ▼
按模块内部规范定位子文件夹
  │
  ▼
目标文件/文件夹已存在？
  ├─ 是 → 先备份，再覆盖
  └─ 否 → 直接保存
```

### 判断说明

1. **Skill / 基础设施文件**
   - 特征：规则、配置、模板、通用脚本
   - 判断口诀：换一个科目/任务是否还能复用？
   - 去向：`.trae/skills/` 或共享配置目录

2. **最终交付物**
   - 特征：用户会查看、使用、长期依赖的文件
   - 示例：HTML 页面、JSON 数据、题目截图、整理后的资料
   - 去向：`Workbench\{模块}\...`

3. **中间产物**
   - 特征：处理过程中临时产生，确认后无长期价值
   - 示例：OCR 文本、一次性脚本、调试日志、草稿、设计 demo
   - 去向：`temp\{模块}\{任务}\`（**唯一合法路径**，禁止在 Workbench 下创建中间产物子目录）

4. **灰色地带（设计稿 / 方案稿 / 参考稿）**
   - 特征：可能有短期参考价值，但不是最终交付物
   - 判断标准：**是否已被最终实现并确认**
     - 已实现并确认满意 → 中间产物，10天后清理
     - 已实现但可能还要参考 → 参考文件，保留到 `temp\{模块}\设计稿\` 或项目文档
     - 还在讨论中、没定稿 → 活跃任务，保留
     - 被否决、没用了 → 中间产物，直接删
   - 存放位置：`temp\{模块}\设计稿\`（或 `temp\设计稿\` 如果跨模块）
   - 生命周期：最多保留 10 天，超期校验脚本警告清理

5. **模块定位**
   - 自考学习相关 → `Workbench\自考学习\`
   - 阅读相关 → `Workbench\阅读\`
   - 新模块按相同模式扩展

6. **冲突处理**
   - 最终交付物覆盖前必须先备份
   - 中间产物直接覆盖（同一任务内可复用临时目录）
   - 遇到模棱两可的情况，先问用户再操作

## 目录结构

### Workbench 根（最终交付物）

```
e:\TraeWorkToDo\Workbench\
  此刻便是春天.html                         # 工作台入口
  自考学习\
    备考科目\
      {课程代码}{课程名称}\
        真题\                               # 原始 PDF 试卷与答案
        真题输出\                             # HTML / JSON / 文本输出
        assets\                              # 题目截图、图表、支撑资源
          exam_figures\
            {year}_q{num}.png
            {year}_q{num}_answer.png
        ...复习资料、综合测验等
    未考科目\
      {课程代码}{课程名称}\
        ...按相同结构扩展
  阅读\
    ...按模块内部规范扩展
```

### 临时目录（中间产物）

```
e:\TraeWorkToDo\temp\
  自考学习\
    {任务标识}\
      处理脚本.py
      草稿.txt
      调试输出\
      OCR中间文本\
      ...
  阅读\
    {任务标识}\
      ...
```

## 文件类型映射

| 文件类型 | 存放位置 | 说明 |
|---|---|---|
| 最终 HTML 页面 | `Workbench\{模块路径}\{输出目录}\` | 模块约定的输出目录，例如 `真题输出\` |
| JSON 数据 | 与对应 HTML 同目录 | 与 HTML 配套使用 |
| 页面配图/题目图 | `Workbench\{模块路径}\assets\{资源子目录}\{命名规则}.png` | 例如 `exam_figures\{year}_q{num}.png`，一题一图，手动确认后裁剪 |
| 解析配图/答案图 | `Workbench\{模块路径}\assets\{资源子目录}\{命名规则}_answer.png` | 解析中需要的附图 |
| 用户上传的原始资料 | `Workbench\{模块路径}\{资料目录}\` | 例如原始 PDF、复习资料，只整理不删除 |
| 处理脚本 | `temp\{模块}\{任务标识}\` | 任务执行成功后即可删除 |
| OCR 中间文本 | `temp\{模块}\{任务标识}\` | 如 `2024.04_questions.txt`，确认输出正确后删除，最多保留 7 天 |
| 调试输出 | `temp\{模块}\{任务标识}\调试输出\` | 问题定位完成后删除 |
| 草稿/试算文件 | `temp\{模块}\{任务标识}\` | 任务结束后删除，不进入版本控制 |
| 备份 | 原文件/目录所在位置下 `{原名}_备份_YYYYMMDD_HHMMSS\` | 覆盖或删除最终交付物前按需保留 |
| 全页原卷/原始扫描页 | 仅在 HTML 内按需展开，不自动保存为单题配图 | 禁止作为题目配图 |

> `{模块路径}`、`{输出目录}`、`{资源子目录}`、`{资料目录}`、`{命名规则}` 由各模块内部规范定义。以 `自考学习` 模块为例：
> - `{模块路径}` = `自考学习\备考科目\{课程代码}{课程名称}`
> - `{输出目录}` = `真题输出`
> - `{资源子目录}` = `exam_figures`
> - `{资料目录}` = `真题`
> - `{命名规则}` = `{year}_q{num}`

## 任务临时目录命名

- 格式：`temp\{模块}\{任务标识}\`
- 任务标识建议：`YYYYMMDD_{简短描述}`，例如 `20260731_离散数学真题生成`
- 同一任务的所有中间产物放在同一任务目录下
- 任务结束后按生命周期规则清理

## 命名规范

- 文件夹：**优先使用中文命名**；当中文会影响引用、URL、跨平台兼容或特定工具解析时，改用拼音
  - 中文示例：`自考学习`、`02324离散数学`、`真题输出`
  - 拼音示例（按需使用）：`zixue`、`lisanshuxu`、`yuedu`
- HTML：`{子模块}-{任务}.html`，例如 `02324离散数学-真题题型归类.html`
- JSON：与对应 HTML 同名，扩展名为 `.json`，例如 `02324离散数学-真题题型归类.json`
- 页面配图：`{命名规则}.png`，例如 `2025.10_q6.png`（具体规则由模块定义）
- 说明/解析配图：`{命名规则}_{后缀}.png`，例如 `2025.10_q6_answer.png`（后缀由模块定义）
- 备份目录：`{原目录名}_备份_YYYYMMDD_HHMMSS`
- 年份格式：`YYYY.MM`，例如 `2025.10`

## 禁止事项

- 自动在 Workbench 之外创建用户可见的项目文件
- 把临时脚本、调试输出保存到 Workbench
- 自动生成全页原卷截图作为题目配图
- 未经人工确认自动裁剪、标注或匹配图片
- 关键词触发式自动截图

## 生命周期管理

### 临时文件

- **处理脚本**（`.py`、`.ps1`、`.sh` 等）：任务执行成功后立即删除
- **OCR 中间文本**（`{year}.{month}_questions.txt`、`{year}.{month}_answers.txt`）：保留到用户确认 HTML/JSON 输出正确后即可删除；最多保留 **10 天**
- **调试输出**（日志、错误截图、堆栈信息）：保留到问题定位完成，随后删除
- **草稿/试算文件**：任务结束后删除，不进入版本控制
- **设计稿 / 方案稿（灰色地带）**：放 `temp\{模块}\设计稿\`，最多保留 **10 天**
  - 已实现并确认的设计稿：到10天校验脚本警告，用户确认后清理
  - 未确定的设计稿：属于活跃任务，保留但需标注状态
- **temp 根目录禁止散落文件**：所有临时文件必须放在 `temp\{模块}\{任务}\` 或 `temp\{模块}\设计稿\` 下，不能直接放在 `temp/` 根目录

### 备份文件

- 触发条件：覆盖或删除最终交付物前、批量重构脚本运行前、用户明确说"先备份"
- 命名：`{原文件/目录名}_备份_YYYYMMDD_HHMMSS`
- 保留策略：同一目标最多保留 3 份历史备份，超出时删除最早的一份
- 清理时机：新备份生成时自动检查；用户也可随时要求"清理旧备份"

### Workbench 内最终交付物

- HTML/JSON/截图：长期保留，按用户要求更新
- 用户主动上传的复习资料、PDF：只整理不删除
- 废弃的试验页面：用户确认后删除
- 每次新增最终交付物后，同步在 `e:\TraeWorkToDo\文件说明.md` 中添加一条解释，说明其用途和能否删除

### 生命周期检查清单

每次任务收尾时执行：

1. 本次任务对应的 `temp\{模块}\{任务}\` 是否还有遗留的脚本/日志？
2. 是否生成了新的备份，需要清理旧备份？
3. Workbench 内是否误放了临时产物？
4. 用户是否需要保留某份中间文件用于调试？
5. 模块下是否还有已结束但未清理的历史任务目录？
6. 是否在 `文件说明.md` 中为新增的最终交付物添加了用途说明？

## 使用示例

用户："把离散数学真题生成 HTML"

→ 模块：`自考学习`
→ 任务标识：`20260731_离散数学真题生成`
→ 读取 PDF 来源：`Workbench\自考学习\备考科目\02324离散数学\真题\`
→ 处理脚本位置：`temp\自考学习\20260731_离散数学真题生成\`
→ 输出位置：`Workbench\自考学习\备考科目\02324离散数学\真题输出\`
→ 输出文件：`02324离散数学-真题题型归类.html`、`02324离散数学-真题题型归类.json`
→ 图片状态：仅标记 `image_status=pending`，不自动配图
